# 学习材料 — 计算广告 / 搜索广告 🔴

> 对应简历: 微软 Meta Smart Match 搜索广告匹配系统 (2022-2024)
> 核心经验: Query-Ad 二部图召回 / Pareto 多目标排序 / NLP Query Rewriting

---

## 1. 搜索广告匹配 / Query-Ad Matching

### 搜索广告匹配论文

- [ ] [DSSM](https://www.microsoft.com/en-us/research/publication/learning-deep-structured-semantic-models-for-web-search-using-clickthrough-data/) — ⭐ MSR, CIKM 2013。微软经典双塔语义匹配。
  - 核心内容：把 query 和 document/ad 分别编码到同一语义向量空间，用点击日志做弱监督，让相关 query-doc 向量更近、不相关更远。
  - 模型直觉：双塔结构牺牲一部分精细交互，换来可离线建索引和在线快速召回。
  - 和 MSM 连接：MSM 的语义召回可以用 DSSM/CDSSM 解释“从字面匹配走向语义匹配”的微软传统；但你项目更强调点击图和 transitive join 补充 embedding 学不到的商业共现。
  - 面试口径：DSSM 解决文本语义匹配，Query-Ad 图解决行为语义匹配；长尾广告召回最好把两类信号结合起来。
  - 风险边界：双塔召回速度快，但 query-ad 细粒度 token 交互弱，容易把语义相近但商业意图不同的广告召进来。
- [ ] [SimRank](https://dl.acm.org/doi/10.1145/775047.775126) — KDD 2002。二部图相似度，对应你的 Transitive Join。
  - 核心内容：两个节点相似，当且仅当它们连接到的邻居也相似；这是“相似由图结构递归定义”的经典思想。
  - 和 MSM 连接：如果两个 query 被同一批 ad 点击，它们可能共享商业意图；如果两个 ad 被同一批 query 点击，它们也可能可替代。
  - 对 Transitive Join 的启发：Q1 -> AdA -> Q2 -> AdB 可以产生 Q1 和 AdB 的候选关系，本质是从共点击图中传播相似性。
  - 面试口径：SimRank 给了二部图相似性的理论直觉，MSM 工程上需要加边权、路径长度限制、degree penalty 和意图过滤。
  - 风险边界：图相似不等于广告相关，热门 hub 会制造伪相似，必须做 Hot Ad 降噪。
- [ ] [Sponsored Search Beyond Keyword Matching](https://dl.acm.org/doi/10.1145/1242572.1242682) — Broder。关键词到语义匹配演进。
  - 核心内容：搜索广告不能只靠 advertiser keyword 的 exact/phrase match，需要理解 query 背后的商业意图并扩展匹配。
  - 业务问题：广告主覆盖不了所有长尾 query；用户 query 和广告主 keyword 的表达方式经常不同。
  - 和 MSM 连接：MSM 正是 broad/semantic match 的一路召回源，用图挖掘和 rewriting 扩大长尾 query 的广告覆盖。
  - 面试口径：这个方向的核心 trade-off 是 coverage vs relevance；扩召回容易涨收入，但也最容易引入 bad match。
  - 风险边界：不能为了 revenue 盲目 broad match，必须用 relevance、投诉率、广告主 ROI 做 guardrail。
- [ ] [A Taxonomy of Web Search](https://dl.acm.org/doi/10.1145/792550.792552) — Broder, SIGIR 2002。Query 意图分类基础。
  - 核心内容：经典地把 web search query 分为 navigational、informational、transactional 三类。
  - 和广告连接：transactional query 商业意图更强，广告可召回空间更大；informational query 可能广告少、RPM 低、体验风险高。
  - 和 MSM 连接：你的 RPM 归因和广告召回都要看 query intent；News/Weather 等低商业意图 query 增加时，RPM 可能自然下降。
  - 面试口径：Query intent 是广告召回的 gate，不能所有 query 都同等扩展。
  - 风险边界：意图分类不是硬规则，同一 query 在不同市场、时间、用户上下文下商业性可能不同。
- [ ] [ColBERT](https://arxiv.org/abs/2004.12832) — SIGIR 2020。BERT Late Interaction。
  - 核心内容：query 和 document 分别编码 token embedding，检索时用 late interaction 计算 token-level 最大相似度，兼顾效率和细粒度匹配。
  - 和双塔区别：双塔把整段压成一个向量，快但损失 token 交互；ColBERT 保留 token 粒度，相关性更强但成本更高。
  - 和 MSM 连接：如果面试官问为什么不用 BERT cross encoder，可以说线上召回成本太高；late interaction 是效果和效率之间的折中参考。
  - 面试口径：MSM 的 L1 不能用太重模型，但 L2 或离线字典生成可以借鉴 late interaction 提升 relevance。
  - 风险边界：模型越重延迟越高，广告系统还要考虑 auction/ranking 全链路 latency budget。

### 搜索广告匹配关键词自测

> DSSM / 双塔模型 / Query-Ad 二部图
> Transitive Join / 高阶关系挖掘 / Random Walk
> 语义召回 / ANN (FAISS/HNSW) / Embedding
> Broad Match / Phrase Match / Exact Match

## 2. Query Rewriting / Query Understanding

### Query Rewriting 论文

- [ ] [BERT](https://arxiv.org/abs/1810.04805) — Google, NAACL 2019。面试必须能讲清楚。
  - 核心内容：Transformer encoder 双向建模上下文，通过 masked language modeling 和 next sentence prediction 预训练，再 fine-tune 到下游任务。
  - 和 query rewriting 连接：BERT 可以用于语义相似、同义词挖掘、query intent 分类、bad match 判断。
  - 工程做法：广告系统里通常离线用 BERT 生成高置信改写/同义词字典，在线用轻量规则或索引服务，不直接把大模型放到最前链路。
  - 面试口径：BERT 负责语义理解，Porter Stemmer 负责词形归一；前者语义强但成本高，后者便宜但容易过度归一。
  - 风险边界：BERT 相似不等于商业意图一致，必须叠加 click graph、intent classifier 和 relevance guardrail。
- [ ] [Porter Stemmer 算法](https://tartarus.org/martin/PorterStemmer/) — stemming vs lemmatization。
  - 核心内容：用规则把英文单词后缀裁剪成词干，例如 running/runs/runner 归到相近形式。
  - 和 MSM 连接：长尾 query 中词形变化很多，stemming 能提升 query-keyword/ad 的表面覆盖。
  - 和 lemmatization 区别：stemming 更快更粗糙，lemmatization 更依赖词性和词典，结果更像合法词。
  - 面试口径：Porter Stemmer 是低成本 recall 扩展工具，但只能处理形态变化，不能解决真正语义同义。
  - 风险边界：过度 stemming 会引入 bad match，特别是品牌词、医疗/金融等敏感 vertical，需要黑白名单和人工抽检。

### Query Understanding 关键词自测

> Porter Stemmer / Lemmatization / Tokenization
> BERT Fine-tuning / Sentence Embedding
> 同义词挖掘 / 同义词词典
> Query Rewriting / Expansion / Suggestion

## 3. 广告排序 / CTR 预估 / 多目标优化

### 广告排序论文

- [ ] [Ad Click Prediction: A View from the Trenches](https://research.google/pubs/pub41159/) — ⭐ Google, KDD 2013。**面试必读**。
  - 核心内容：大规模广告 CTR 预估的工程实践，重点是稀疏高维特征、在线学习、FTRL-Proximal、正则化和校准。
  - 为什么重要：搜索广告收益通常近似 `bid * pCTR`，pCTR 估不准会同时伤害平台收入、广告主 ROI 和用户体验。
  - 和 MSM 连接：MSM 的 Revenue/CTR 目标必须依赖可靠 pCTR 或历史 CTR 特征，否则 Pareto 空间里的 revenue 维度会不稳。
  - 面试口径：广告排序不是只拼模型结构，更重要是特征、校准、在线更新、延迟和数据分布漂移。
  - 风险边界：AUC 高不代表 revenue 一定高，CTR calibration 和分桶稳定性同样重要。
- [ ] [Practical Lessons — Facebook](https://research.facebook.com/publications/practical-lessons-from-predicting-clicks-on-ads-at-facebook/) — ⭐ GBDT+LR 经典。
  - 核心内容：用 GBDT 学非线性特征组合，再把叶子节点作为离散特征喂给 LR，兼顾表达能力和线上效率。
  - 工程直觉：树模型自动做特征交叉，LR 负责大规模稀疏线性学习，部署简单稳定。
  - 和 MSM 连接：L1/L2 筛选可以用轻量模型和 engineered features，不一定每层都上深模型。
  - 面试口径：广告系统里简单稳定模型仍有价值，尤其在高 QPS、低延迟、强可解释要求的召回/粗筛阶段。
  - 风险边界：GBDT+LR 对稀疏 ID、长尾泛化和实时兴趣表达不如深度模型。
- [ ] [Wide & Deep](https://arxiv.org/abs/1606.07792) — Google, 2016。面试必考。
  - 核心内容：Wide 部分记忆高频共现和人工交叉特征，Deep 部分学习泛化能力。
  - 广告解释：Wide 能记住明确商业规则或历史强特征，Deep 能泛化到未见过的 query-ad 组合。
  - 和 MSM 连接：语义召回既需要覆盖长尾，也需要避免忘记强规则和黑白名单，Wide & Deep 是这种 trade-off 的经典表达。
  - 面试口径：Wide & Deep 本质是 memorization + generalization，广告系统需要二者平衡。
  - 风险边界：人工 cross 维护成本高，deep 部分如果缺少约束可能引入不可解释 bad match。
- [ ] [DeepFM](https://arxiv.org/abs/1703.04247) — IJCAI 2017。FM + DNN。
  - 核心内容：FM 显式建模二阶特征交叉，DNN 学高阶非线性交叉，两部分共享 embedding。
  - 和广告连接：CTR 特征大量是 user/query/ad/context/category 的稀疏组合，FM 系列适合学习交叉信号。
  - 和 MSM 连接：如果 L2 要做 query-ad quality scoring，可以用 DeepFM 类思想融合离散特征、历史统计和语义特征。
  - 面试口径：DeepFM 比 Wide & Deep 更自动化地学习低阶交叉，减少手工 wide feature。
  - 风险边界：特征穿越、训练/服务不一致、embedding 冷启动会直接影响线上效果。
- [ ] [DIN](https://arxiv.org/abs/1706.06978) — 阿里, KDD 2018。注意力 CTR 预估。
  - 核心内容：根据候选 item/ad 对用户历史行为做 attention，动态抽取与当前候选最相关的兴趣。
  - 和广告连接：用户对不同 query/ad 的兴趣不同，候选相关的历史行为比全局平均兴趣更有效。
  - 和 MSM 连接：搜索广告强 query intent，用户历史可作为 ranking 阶段特征，但 MSM 召回阶段更重 query-ad 语义和点击图。
  - 面试口径：DIN 说明排序阶段可以做候选相关兴趣建模，但召回阶段要受 latency 和候选规模限制。
  - 风险边界：用户行为稀疏或隐私限制时，DIN 类模型效果会受影响。
- [ ] [DCN V2](https://arxiv.org/abs/2008.13535) — Google, WWW 2021。特征交叉。
  - 核心内容：用 cross network 显式学习 bounded-degree feature crosses，并改进参数化方式提高表达能力。
  - 和广告连接：广告排序高度依赖特征交叉，例如 query intent × ad vertical × device × market。
  - 和 MSM 连接：L2 scoring 可以用 cross 特征判断某个 query-ad 在特定市场/设备是否高质量。
  - 面试口径：DCN 类模型适合解释为什么纯 DNN 不一定最稳，显式交叉能提升可控性和样本效率。
  - 风险边界：特征交叉过多会带来过拟合和部署复杂度。
- [ ] [Pareto-Efficient Multi-Objective](https://dl.acm.org/doi/10.1145/3298689.3346998) — RecSys 2019。
  - 核心内容：多目标优化不能简单用单一指标代表所有目标，Pareto frontier 保留不被全面支配的解。
  - 和 MSM 连接：L1 阶段要同时看 Revenue、CTR、Relevance，避免 revenue 单目标杀掉高相关候选。
  - 工程转译：线上不一定完整求 Pareto frontier，可以用归一化加权、constraint、分桶 topK 等近似。
  - 面试口径：Pareto 思想帮助 L1 保留多目标多样性，把最终权衡留给 L2 和下游 ranking/auction。
  - 风险边界：Pareto 候选太多会增加 latency，必须控制 TopK 和 guardrail。

### 广告排序关键词自测

> CTR 模型链: LR → GBDT+LR → FM → Wide&Deep → DeepFM → DCN → DIN
> eCPM = bid × pCTR (× pCVR)
> Pareto Optimality / Front / Linear Scalarization
> PID 动态调参 / Constrained Optimization / Lagrangian
> Calibration / Logloss / AUC / GAUC

## 4. Auction 机制 & Bid 策略

### Auction 论文

- [ ] [GSP Auction](https://www.benedelman.org/publications/gsp-060801.pdf) — ⭐ AER 2007。**面试必问**。
  - 核心内容：搜索广告位置拍卖中，广告主按排名获得位置，通常支付下一位广告主的某种价格，而不是自己的出价。
  - 关键概念：bid、quality score、pCTR、rank score、actual CPC、reserve price。
  - 和 MSM 连接：MSM 主要负责候选生成和质量筛选，不直接决定拍卖价格；但候选质量会影响下游 auction 的可选空间。
  - 面试口径：搜索广告链路要区分 matching、ranking、auction、billing；MSM 是 matching/quality stage，不是 billing system。
  - 风险边界：不能只优化平台 RPM，广告主 ROI 和用户 relevance 会影响长期生态。
- [ ] [Position Auctions — Varian](https://people.ischool.berkeley.edu/~hal/Papers/2006/position.pdf) — 2007。
  - 核心内容：分析 sponsored search 中位置价值、广告主出价和均衡价格。
  - 直觉：不同位置点击率不同，广告主根据预期收益竞争位置。
  - 和 MSM 连接：召回更多相关广告会改变 auction competition density，从而影响 RPM 和 advertiser outcomes。
  - 面试口径：召回系统提升 revenue 的一部分来自提高广告候选深度和竞争强度，但必须确保相关性。
  - 风险边界：提高竞争不等于提高整体效率，如果召回低质量广告，会伤用户和广告主。
- [ ] [RTB with Multi-Agent RL](https://arxiv.org/abs/1802.09756) — CIKM 2018。
  - 核心内容：在实时竞价场景下，多个 bidder 学习预算约束下的出价策略。
  - 和搜索广告区别：RTB 更偏 display/ad exchange，搜索广告强 query intent 和位置拍卖；二者都涉及预算、竞价和 ROI。
  - 和 MSM 连接：可用于理解广告主侧 bidding/pacing，但 MSM 自身更靠近平台 matching，不是 bidder 策略。
  - 面试口径：我了解 bidding/pacing 生态，但我的项目优化的是召回质量和多目标筛选，不直接做 advertiser bidding。
  - 风险边界：RL 出价探索成本高，线上广告系统通常要强约束和离线仿真。

### Auction 关键词自测

> GSP / VCG 拍卖 / First-Price vs Second-Price
> Reserve Price / Quality Score
> Pacing / Budget Smoothing
> RTB / DSP / SSP / Ad Exchange
> Smart Bidding / Auto Bidding / ROI / CPA 约束
> Nash Equilibrium / Incentive Compatibility

## 5. 经典书籍 & 课程

- [ ] **《计算广告》— 刘鹏、王超** — ⭐⭐⭐ 面试前必通读。
  - 重点内容：广告检索、CTR 预估、点击价值估计、竞价机制、预算控制、广告交易市场。
  - 和 MSM 连接：用它补全“MSM 在广告系统哪一层”的全局视角，避免把召回、排序、拍卖混在一起讲。
  - 面试口径：我会把搜索广告拆成 matching、prediction、ranking、auction、feedback 五层，再定位 MSM 的贡献。
- [ ] **《深度学习推荐系统》— 王喆** — CTR/Embedding/特征工程。
  - 重点内容：Embedding、CTR 模型演进、召回/排序架构、特征工程、推荐系统工程化。
  - 和 MSM 连接：广告 CTR 和推荐 CTR 很多模型共通，区别是广告多了 bid、auction、advertiser ROI 和合规约束。
  - 面试口径：推荐系统优化用户满意和平台目标，广告系统还要额外平衡广告主和拍卖机制。
- [ ] [Introduction to IR (免费)](https://nlp.stanford.edu/IR-book/) — 倒排索引、TF-IDF、BM25。
  - 重点内容：term weighting、inverted index、BM25、link analysis、evaluation。
  - 和 MSM 连接：Hot Ad degree penalty 可以用 IDF 直觉解释，query-keyword 匹配也离不开 IR 基础。
  - 面试口径：语义匹配不是替代 IR，而是在传统 IR 之上增加行为图和 embedding 信号。
- [ ] [Stanford CS364A: Algorithmic Game Theory](http://timroughgarden.org/f13/f13.html) — GSP/VCG。
  - 重点内容：拍卖、机制设计、激励相容、均衡、福利和收入权衡。
  - 和 MSM 连接：理解 downstream auction 后，更容易解释为什么召回质量会影响广告市场生态。
  - 面试口径：匹配系统增加候选供给，拍卖机制决定如何分配展示和价格；两个层次要解耦优化。
- [ ] [Stanford CS246: Mining Massive Datasets](http://web.stanford.edu/class/cs246/)。
  - 重点内容：大规模图挖掘、PageRank、SimRank、频繁项集、推荐系统、海量数据处理。
  - 和 MSM 连接：Query-Ad 点击图、Hot Ad hub 降噪、transitive join 都属于大规模图挖掘问题。
  - 面试口径：MSM 的图挖掘不是玩具图算法，而是大规模日志、边权、去噪、增量更新和服务化输出。

## 8. 深化阅读地图：按 MSM 简历点反推

> 目标是让「Query-Ad 二部图召回 + Pareto 多目标筛选」不只停留在项目描述，而能讲清搜索广告系统、检索匹配、拍卖机制和实验评估。

### 8.1 Query-Ad Matching / Semantic Retrieval

- [ ] [CDSSM: Convolutional Latent Semantic Model](https://www.microsoft.com/en-us/research/publication/a-latent-semantic-model-with-convolutional-pooling-structure-for-information-retrieval/) — MSR。DSSM 的卷积版本。
  - 核心内容：在 DSSM 基础上加入卷积和 pooling，更好捕捉局部词序和 n-gram 语义。
  - 和 MSM 连接：适合解释 query/ad/keyword 的短文本语义匹配，尤其是 query 很短时局部 phrase 很重要。
  - 面试口径：DSSM/CDSSM 是微软语义检索传统，但 MSM 还需要点击图，因为广告商业意图不总是文本相似。
- [ ] [Duet: Local and Distributed Representations for Web Search](https://www.microsoft.com/en-us/research/publication/learning-to-match-using-local-and-distributed-representations-of-text-for-web-search/) — MSR。精确匹配 + 语义匹配双通道。
  - 核心内容：local model 捕捉 exact term match，distributed model 捕捉语义相似，两路互补。
  - 和广告连接：搜索广告也不能只用 exact match 或只用 semantic match；品牌词、强商业词需要精确匹配保护。
  - 面试口径：MSM 的价值不是替代 exact/phrase match，而是补长尾语义召回；Duet 正好说明精确和语义应并存。
- [ ] [DRMM: Deep Relevance Matching Model](https://arxiv.org/abs/1711.08611) — 文本相关性匹配经典模型。
  - 核心内容：用 query term 和 document term 的 matching histogram 建模相关性，强调 query term 粒度的重要性。
  - 和 MSM 连接：Relevance 不能只看整体 embedding cosine，某些 query token 如品牌、型号、地域非常关键。
  - 面试口径：广告 bad match 常常来自关键 token 被语义模型抹平，所以 L2 要保留 term-level relevance feature。
- [ ] [ANCE: Approximate Nearest Neighbor Negative Contrastive Learning](https://arxiv.org/abs/2007.00808) — 稠密检索训练与 hard negative。
  - 核心内容：用 ANN 检索当前模型容易混淆的 hard negatives，再迭代训练 dense retriever。
  - 和 MSM 连接：Query-Ad embedding 召回的难点不是召回相似，而是区分“语义相似但商业不相关”的 hard negative。
  - 面试口径：广告语义召回训练必须重视 hard negatives，比如 informational vs transactional 的近似 query。
- [ ] [ColBERTv2](https://arxiv.org/abs/2112.01488) — Late interaction 检索模型。
  - 核心内容：通过 late interaction 和压缩技术提升 ColBERT 的效率与效果。
  - 和 MSM 连接：可作为 L2 或离线打分参考，提高 relevance，而不是放在超高 QPS 的最前召回层。
  - 面试口径：双塔适合召回，late interaction 适合精筛，cross encoder 适合离线或小候选 rerank。
- [ ] [Learning to Rank for Information Retrieval](https://www.nowpublishers.com/article/Details/INR-016) — Tie-Yan Liu 经典综述。
  - 核心内容：系统总结 pointwise、pairwise、listwise LTR，以及 ranking loss、特征、评估指标。
  - 和 MSM 连接：L1/L2 scoring 都是排序问题，只是 MSM 内部排序不是全局广告最终排序。
  - 面试口径：要主动澄清 MSM L1/L2 是候选质量漏斗，下游还有 auction/ranking。

读完要能回答：

- Exact/Phrase/Broad Match、语义召回、Query Rewriting 在系统中分别承担什么角色？
- 双塔、Late Interaction、Cross Encoder 的延迟和效果权衡是什么？
- 为什么图挖掘能发现 embedding 不容易学到的非直观共现关系？
- Query-Ad 相关性如何离线标注和在线评估？

### 8.2 图挖掘与 Hot Ad 降噪

- [ ] [SimRank](https://dl.acm.org/doi/10.1145/775047.775126) — 二部图相似度基础，直接映射 Transitive Join 的直觉。
  - 核心内容：相似来自相似邻居，适合解释 query-query、ad-ad 在点击图上的递归相似。
  - MSM 用法：把 SimRank 作为理论直觉，工程上用有限跳数 transitive join 和 edge weight 近似。
  - 风险：递归传播容易把 hub 噪声放大，所以必须有 degree penalty。
- [ ] [Personalized PageRank](https://nlp.stanford.edu/IR-book/html/htmledition/pagerank-1.html) — 图随机游走基础。
  - 核心内容：从某个起点出发随机游走，带 restart，得到相对该起点的节点重要性。
  - MSM 用法：可以解释从 query 出发沿点击图传播到候选 ad 的过程，restart 控制不跑太远。
  - 面试口径：PPR 比简单 transitive join 更平滑，但计算和更新成本更高，工程上要看规模和延迟。
- [ ] [Mining of Massive Datasets: Link Analysis](http://www.mmds.org/) — 大规模图挖掘章节。
  - 核心内容：PageRank、HITS、hub/authority、链接垃圾、图规模化计算。
  - MSM 用法：Hot Ad 可以看作 hub 节点，连接太多 query 时会污染语义传播。
  - 面试口径：MSM 的 Hot Ad degree penalty 本质是在广告点击图里做 hub 降噪。
- [ ] [TF-IDF / BM25 — Stanford IR Book](https://nlp.stanford.edu/IR-book/) — 用 IR 的 IDF 直觉解释 Hot Ad degree 惩罚。
  - 核心内容：越常见的 term 区分度越低，IDF 降低 common term 权重。
  - MSM 类比：被太多 query 点击的 ad 区分度低，作为桥节点时应该降权。
  - 面试口径：Hot Ad 惩罚不是惩罚热门广告展示，而是惩罚它在图传播中制造伪相关。

读完要能回答：

- Hot Ad 为什么是 Hub 节点噪声？硬过滤和软降权各有什么风险？
- Q1 -> Ad -> Q2 -> Ad2 的多跳路径如何避免语义漂移？
- Degree 惩罚公式怎么设计？按 Ad degree、Query degree 还是边权一起归一化？
- 如何用点击数、转化数、广告覆盖率过滤低质量边？

### 8.3 广告排序、拍卖与出价

- [ ] [FTRL-Proximal / Ad Click Prediction](https://research.google/pubs/pub41159/) — Google KDD 2013。大规模广告 CTR 预估工程基础。
  - 核心内容：FTRL 适合高维稀疏在线学习，兼顾 L1 稀疏、L2 稳定和在线更新。
  - MSM 用法：L1/L2 里的 CTRScore 或 historical CTR feature 必须有稳定预估基础。
  - 面试口径：广告 CTR 不是单纯模型问题，还涉及在线学习、校准、特征新鲜度和分桶稳定性。
- [ ] [Practical Lessons from Predicting Clicks on Ads at Facebook](https://research.facebook.com/publications/practical-lessons-from-predicting-clicks-on-ads-at-facebook/) — GBDT+LR 经典实践。
  - 核心内容：GBDT 自动挖交叉，LR 负责稀疏线性预测，是深度模型之前非常强的工业基线。
  - MSM 用法：在候选筛选阶段，轻量模型常常比重模型更可控，适合低延迟质量过滤。
  - 面试口径：广告系统不是模型越深越好，要根据链路位置选择 latency/effect trade-off。
- [ ] [Real-Time Bidding by Reinforcement Learning](https://arxiv.org/abs/1802.09756) — RTB 出价策略材料。
  - 核心内容：把 bidding 看成序列决策，在预算约束下最大化点击/转化/收益。
  - MSM 用法：帮助理解 advertiser bidding 侧生态，但 MSM 更偏平台候选供给，不直接控制广告主出价。
  - 面试口径：我知道 bidding 是下游重要因素，但简历项目主要贡献在 matching quality 和 candidate funnel。
- [ ] [Optimal Real-Time Bidding for Display Advertising](https://arxiv.org/abs/1407.7073) — 预算约束下的竞价优化。
  - 核心内容：在预算和市场价格分布约束下选择最优 bid。
  - MSM 用法：理解为什么 advertiser ROI 和 budget pacing 是 guardrail，不应只看平台 RPM。
  - 面试口径：召回扩展如果带来低质点击，会影响广告主 ROI，长期会反噬平台收入。
- [ ] [Pacing Equilibria in First Price Auction Markets](https://arxiv.org/abs/1706.07151) — 预算节奏控制理论。
  - 核心内容：预算有限时，广告主需要 pacing multiplier 控制花费速度，市场存在均衡问题。
  - MSM 用法：召回候选变化会影响 auction competition 和预算消耗节奏。
  - 面试口径：matching、ranking、pacing 不是同一层，但它们通过候选供给和竞价压力相互影响。
- [ ] [Stanford CS364A: Algorithmic Game Theory](http://timroughgarden.org/f13/f13.html) — 拍卖理论系统复习。
  - 核心内容：机制设计、拍卖、均衡、福利和收入理论。
  - MSM 用法：用于回答高级追问：平台收益、广告主激励、用户体验如何共同约束广告系统。
  - 面试口径：我不会把语义召回优化说成孤立 revenue hack，而是放在广告市场机制里看长期效果。

## 13. 公式与概念卡

### Query-Ad 图候选分

```text
score(q, ad2) = sum over paths q -> ad1 -> q2 -> ad2:
                w(q, ad1) * w(q2, ad1) * w(q2, ad2)
                * degree_penalty(ad1)
                * intent_consistency(q, q2)
```

解释顺序：

- `w(q, ad)`：点击、转化、revenue、rank position、时间衰减都可作为边权。
- `degree_penalty(ad)`：抑制热门广告 hub 噪声。
- `intent_consistency`：防止 informational query 和 transactional query 互相污染。

### Hot Ad 惩罚

```text
penalty_1 = 1 / log(1 + degree(ad))
penalty_2 = 1 / sqrt(degree(ad))
penalty_3 = idf(ad_vertical) * edge_confidence
```

面试表达：

- degree penalty 不是为了惩罚热门广告本身，而是为了降低「热门广告作为桥」时制造伪相关的能力。
- 头部 query 不能简单硬过滤 hot ad，否则会损失真实商业覆盖。

### Pareto 支配关系

```text
A dominates B if:
  A.revenue >= B.revenue
  A.ctr >= B.ctr
  A.relevance >= B.relevance
and at least one dimension is strictly better.
```

解释顺序：

- L1 先保住多目标候选多样性。
- L2 再用更重模型、更细特征、更严格规则精筛。
- 最终全局广告排序仍由下游 auction/ranking 决定。

### RPM 与 Revenue

```text
RPM = revenue / impressions * 1000
expected_revenue ≈ pCTR * bid * quality_adjustment
```

风险边界：

- RPM 上升不一定代表用户体验上升。
- Revenue 上升要同时看 relevance、CTR、complaint、advertiser ROI、latency。

## 14. MSM 系统设计模板

### 离线链路

1. 收集 query/ad/keyword/click/conversion 日志。
2. 做 normalization：lowercase、tokenization、stemming、语言识别、market 分桶。
3. 构建 Query-Ad / Query-Keyword 二部图。
4. 运行 transitive join / random walk 生成候选。
5. 加入 NLP rewriting 和同义词扩展。
6. 计算 edge quality、degree penalty、intent consistency、relevance score。
7. 进入 L1/L2 筛选，产出语义匹配候选表。

### 在线链路

1. 用户 query 进入搜索广告系统。
2. MSM 作为一路召回源返回候选 ad/keyword。
3. 候选与 exact/phrase/其他 broad match 源去重融合。
4. 下游 ranking/auction 计算最终展示。
5. 点击、转化、投诉、relevance label 回流离线训练。

### 关键保护

- Query intent gate：低商业意图 query 降低广告扩展强度。
- Market/language gate：不同语言不能共享同一 stemming 规则。
- Advertiser safety：品牌词、敏感词、合规行业需要额外规则。
- Latency budget：MSM 输出 TopK 受控，不能拖慢下游。

| 层级 | 指标 | 作用 | 可能异常 |
| ---- | ---- | ---- | -------- |
| Primary | RPM / Revenue | 判断商业收益 | 被季节性、竞价环境影响 |
| User Guardrail | CTR / quick back / complaint | 保护体验 | CTR 升但 relevance 降 |
| Advertiser Guardrail | CPA / ROI / conversion quality | 保护广告主 | 低质点击增加 |
| Supply Diagnostic | query coverage / ad depth | 看召回是否扩展 | coverage 升但质量差 |
| Quality Diagnostic | relevance label / bad match rate | 看语义匹配质量 | 长尾 query 漂移 |
| System | latency / timeout / cost | 保护服务 | TopK 过大或模型过重 |

RPM +1.8% 回答骨架：

1. 随机分桶，control/treatment 同期比较。
2. 分 market、device、query bucket、commercial intent 看一致性。
3. 看 guardrail：relevance、CTR、complaint、latency、advertiser ROI。
4. 用 pre-period 指标或 CUPED 降低方差。
5. 做 holdout 或 ramp-up，避免 novelty effect。

## 16. 高频追问答案素材

- Q：为什么图挖掘不被 embedding 替代？
  - A：Embedding 学文本语义，图挖掘学真实商业行为。长尾 query 文本稀疏，但点击共现能暴露商业意图。
- Q：Transitive Join 路径越长越好吗？
  - A：不是。路径越长覆盖越高但语义漂移越强，通常限制 2-hop/3-hop，并用边权、degree penalty、intent gate 控制。
- Q：为什么不按 eCPM 直接截断？
  - A：L1 杀错不可逆。只按 eCPM 会杀掉低 bid 但高相关的候选，影响用户体验和下游多样性。
- Q：相关性下降但收入上升能上线吗？
  - A：不能只看收入。要看 relevance 下降幅度、投诉、长期 CTR、广告主 ROI 和实验持续性；成熟系统通常有硬 guardrail。
- Q：MSM 的收益如何归因？
  - A：需要按召回源打标，记录候选来自 MSM 的贡献，再看曝光、点击、收入、被下游排序保留比例和去重后增量。
