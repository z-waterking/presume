## 1. 搜索广告系统全景图（必背）

```text
Query
 │
 ├── Query Understanding (intent / language / vertical / geo)
 │
 ├── Matching Layer
 │     ├── Exact Match
 │     ├── Phrase Match
 │     ├── Broad Match
 │     ├── Semantic Recall (DSSM/Two-tower)
 │     ├── MSM Graph Recall  ← 你的项目
 │     └── Rewriting Recall (stem / synonym / BERT)
 │
 ├── Candidate Merge / Dedup / Quality Filter
 │
 ├── Ranking Layer (pCTR · bid · quality)
 │
 ├── Auction (GSP, reserve, pacing)
 │
 ├── Impression / Click
 │
 └── Feedback (click / conv / complaint) → 离线训练 + 图重建 + 实验评估
```

**关键澄清**：MSM 是 Matching Layer 的一路语义召回源 + 内部 L1/L2 质量漏斗，**不**是全局 ranking / auction。

## 2. Query-Ad 二部图：完整公式与工程

### 2.1 候选生成公式

```text
score(q_src, ad_tgt) = Σ_{path: q_src → ad_pivot → q_pivot → ad_tgt}
        w(q_src, ad_pivot)
      · w(q_pivot, ad_pivot)
      · w(q_pivot, ad_tgt)
      · degree_penalty(ad_pivot)
      · intent_consistency(q_src, q_pivot)
      · time_decay(t)
```

每个因子的工程含义：

- `w(q,a)` = 加权点击信号，可以是 `clicks · CTR · conv · revenue` 的归一化组合。
- `degree_penalty` = 惩罚 hub ad，常见三种：
  ```text
  penalty_log    = 1 / log(1 + deg(a))
  penalty_sqrt   = 1 / sqrt(deg(a))
  penalty_idf    = log(N / (1 + deg(a)))
  ```
- `intent_consistency` = `cos(intent_emb(q_src), intent_emb(q_pivot))`，防止 informational ↔ transactional 串扰。
- `time_decay` = `exp(-λ Δt)`，旧点击衰减。

### 2.2 路径长度选择

| 跳数 | 覆盖 | 噪声 | 适合 |
| ---- | ---- | ---- | ---- |
| 1-hop（直接共现） | 低 | 低 | 头部稳健 |
| 2-hop（默认） | 中 | 中 | 主力 |
| 3-hop | 高 | 高 | 长尾，需更强降噪 |
| ≥4-hop | 很高 | 失控 | 不建议 |

### 2.3 SimRank vs PPR vs Transitive Join

- **SimRank**：递归相似度，理论优雅但全图迭代成本高，工业界很少直接用。
- **PPR (Personalized PageRank)**：从 query 出发带 restart 的随机游走，平滑、可分布式。
- **Transitive Join (你的方案)**：限定 hop 的硬路径，工程简单、可解释、易做 degree penalty。

**讲法**：SimRank 是"为什么有效"的理论根，工程落地走 transitive join 是因为可解释、可调、可服务化。

## 3. NLP Rewriting：Stemmer + BERT pipeline

### 3.1 离线 pipeline

```text
1) raw query log
2) language detect / market 分桶
3) tokenize (lang-specific)
4) lemmatize / stem (Porter for en, language-specific for others)
5) generate candidate rewrites:
     a) BERT MLM 同义词
     b) co-click query-query 同义对
     c) translation memory（多语言市场）
6) score each rewrite by:
     intent consistency + click-graph support + market frequency
7) precision filter (threshold ≥ 0.85)
8) bad-match audit (sample + manual)
9) blacklist (brand / pharma / political / minor)
10) freeze 同义词字典 + 版本号上线
```

### 3.2 上线时

- 在线只查字典，不在线跑大模型。
- 字典按 `lang × market × intent` 分桶。
- 每个 rewrite 携带 confidence；低置信只用作召回 hint，不进 broad match。

### 3.3 Stemmer vs Lemmatizer

| 维度 | Stemmer (Porter) | Lemmatizer |
| ---- | ---------------- | ---------- |
| 速度 | 极快 | 慢（需词典/词性） |
| 正确性 | 启发式，会过截 | 高 |
| 多语言 | 各语言单独算法 | 依赖语言资源 |
| 适合 | 召回扩展（粗） | 精筛 / 标注 |

## 4. Pareto 多目标 L1：完整推导

### 4.1 支配关系

```text
A ≻ B  iff  A.r ≥ B.r ∧ A.ctr ≥ B.ctr ∧ A.rel ≥ B.rel
        ∧ (A 在至少一维严格大于 B)
```

Pareto frontier = 不被任何其他点支配的点集合。

### 4.2 几何直觉

- Linear Scalarization `f = Σ w_i · x_i` 等价于用一个超平面在多目标空间扫切线，切到的点都在 **凸 frontier** 上。
- **非凸 frontier 上的点永远扫不到** —— 这是 Linear Scalarization 的根本局限。

### 4.3 三种解法对比

| 方法 | 能扫非凸 | 计算成本 | 工程难度 |
| ---- | -------- | -------- | -------- |
| Linear Scalarization | ❌ | O(n) | 低 |
| ε-Constraint | ✅ | O(n · k) | 中 |
| Tchebycheff | ✅（理论全） | O(n · k) | 中高 |
| NSGA-II（进化算法） | ✅ | 高 | 高，少用线上 |

**ε-Constraint 形式**：
```text
maximize  revenue
s.t.      relevance ≥ ε_rel
          ctr       ≥ ε_ctr
```

**Tchebycheff**：
```text
minimize max_i { λ_i · | x_i - x_i* | }
```

### 4.4 为什么 L1 用 Pareto 不用 eCPM 单截

1. **L1 杀错不可逆**：低 bid 高相关候选被截掉，L2 再好也救不回来。
2. **保留多目标多样性**：给 L2 / 下游 ranking 一个非退化候选集。
3. **几乎零额外算力**：Pareto 在小候选集上 O(n²)；线上常用近似（按维度排序后 sweep）做到 O(n log n)。

### 4.5 30 秒口径

> L1 用 Pareto 是因为它一旦杀错不可逆。线性单目标��扼杀低 bid 高相关候选，破坏 L2 的选择空间。Linear Scalarization 在凸 frontier 上够用，硬约束相关性下限来兜底，非凸场景留给 ε-Constraint。

## 5. 拍卖机制：GSP / VCG / Quality Score

### 5.1 GSP 核心

广告位 i 的实际点击价格：

```text
cpc_i = (bid_{i+1} · qs_{i+1}) / qs_i + δ
```

其中 `qs` 是 quality score（与 pCTR、相关性、landing page 质量相关）。

性质：**GSP 不是激励相容**（VCG 才是），但工程实现简单、广告主直觉好理解，所以行业默认 GSP。

### 5.2 VCG 简述

每个广告主支付"自己存在导致他人外部性"的部分。激励相容、福利最优，但价格可解释性差，少用于搜索广告。

### 5.3 Quality Score 的作用

- 防止"出价高但不相关"霸屏。
- 把用户体验嵌入价格机制：rel 高 → 同样位置 cpc 更便宜。

### 5.4 Reserve Price 与 Pacing

- **Reserve**：低于此价不参与拍卖；保护底价，但过高会减少竞争。
- **Pacing multiplier**：按预算消耗速度对 bid 做缩放，平滑预算。

### 5.5 召回扩展如何影响拍卖

更多候选 → 更激烈竞争 → CPC 上升、平台收入上升；但若候选质量差，CTR、relevance、ROI 全下来，长期反噬。**这正是 MSM 必须有 quality guardrail 的根本原因。**

## 6. CTR 预估：从 FTRL 到 DIN（广告侧重点）

### 6.1 FTRL-Proximal（必背）

```text
w_t = arg min_w  Σ_{s≤t} g_s · w + (1/2) Σ_{s≤t} σ_s · ||w - w_s||² + λ_1 ||w||_1
```

要点：
- 在线学习，逐样本更新。
- L1 正则产生稀疏，部署省内存。
- 学习率 per-coordinate，稀疏特征不会被淹。

### 6.2 Calibration 为什么重要

广告 `eCPM = bid · pCTR`，pCTR 偏 0.1 会让 eCPM 偏 10%。AUC 高不等于 calibration 好（AUC 只关心序）。

校准方法：
- **Platt Scaling**：sigmoid(a · pCTR + b)，简单。
- **Isotonic Regression**：单调映射，更灵活但需要更多样本。
- **Calibration by bucket**：按 query / market / hour 分桶单独校准。

### 6.3 GAUC

广告系统更看 user-level / query-level AUC 平均（GAUC），因为不同 user/query 不可比。

```text
GAUC = Σ_u w_u · AUC_u / Σ_u w_u
```

## 7. 实验评估：RPM +1.8% 怎么讲可信

### 7.1 实验指标层级

| 层级 | 指标 | 作用 |
| ---- | ---- | ---- |
| Primary | RPM / Revenue | 商业收益 |
| User guardrail | CTR、quick back、complaint | 体验 |
| Advertiser guardrail | CPA、ROAS、conv quality | 广告主 ROI |
| Diagnostic | coverage、ad depth、dedup contribution | 召回扩展是否真扩 |
| Quality | relevance label、bad match rate | 语义质量 |
| System | P95 latency、timeout、cost | 服务健康 |

### 7.2 标准回答骨架（5 段）

1. **同期 A/B**：control / treatment 同时跑，避免季节性。
2. **分桶切片**：market、device、query bucket、commercial intent，全部一致才认。
3. **Guardrail 全绿**：relevance、CTR、complaint、advertiser ROI、latency 不越线。
4. **方差控制**：CUPED 用 pre-period 协变量降方差，确保 1.8% 的小 lift 显著。
5. **Hold-out / ramp**：novelty effect、carryover、SRM 全部检查；分阶段 ramp 5% → 25% → 50% → 100%。

### 7.3 反驳"是不是季节性"标准答案

> control 和 treatment 是同期同流量随机分桶，季节性会同时影响两组；如果 treatment 相对 control 在多市场、多设备、多 query bucket 都正向，且 guardrail 稳定，方可认为是算法增量。我们还会用 pre-period CUPED 校准，确保小 lift 在 99% 置信下显著。

## 8. MSM 系统设计：5 分钟讲完

1. **离线**：query/ad/keyword/click/conv 日志 → normalization → Query-Ad 二部图 → transitive join → NLP rewriting → edge quality / degree penalty / intent gate → L1（Pareto）→ L2（精筛）→ 候选表。
2. **在线**：用户 query → query understanding → MSM 召回（查候选表 + 实时 rewriting）→ 与其他召回源 merge / dedup → 下游 ranking + auction → 展示。
3. **Quality**：query intent gate（低商业意图降权）、market/language gate、advertiser safety、latency budget（TopK 受控）。
4. **反馈**：曝光、点击、转化、relevance label、investor complaint → 回流离线，更新边权和 L2 模型。
5. **A/B**：primary RPM + 5 类 guardrail，分桶切片，CUPED，分阶段 ramp。

## 9. 高频追问的标准答案段（背 8 段）

1. **为什么不用纯 embedding 召回？** Embedding 学文本语义，但搜索广告关心商业意图。点击图直接来自真实广告交互，能发现文本不相似但商业相近的关系。最稳是图 + rewriting + embedding 多路互补。

2. **Hot Ad 软降权 vs 硬过滤？** 硬过滤会伤害头部商业 query，因为热门广告对某些 query 真的相关。软降权只削弱它做"桥节点"传播语义的能力，保留高质量直接边。

3. **Query rewriting 怎么防漂移？** 离线高置信 + 按 market/lang/intent 分桶 + 人工抽检 + 在线黑白名单 + relevance threshold + bad match guardrail。

4. **L1 为什么 Pareto？** L1 杀错不可逆，单目标截断会扼杀低 bid 高相关候选；Pareto 保多目标多样性，把权衡留给 L2 和下游 ranking。

5. **Linear Scalarization 局限？** 只能扫凸 frontier。非凸场景用 ε-Constraint（把次目标做约束）或 Tchebycheff（最小化与理想点最大偏差）。线上 frontier 大多近似凸 + relevance hard constraint 兜底，工程足够。

6. **RPM +1.8% 是季节性吗？** 同期 A/B + 分桶切片一致 + guardrail 全绿 + CUPED 显著 + 分阶段 ramp 稳定。

7. **相关性下降但 RPM 上升能上线吗？** 不一定。看 relevance 下降幅度、complaint、长期 CTR、advertiser ROI；通常有 hard relevance 下限作为 guardrail，不能为短期收入越线。

8. **MSM 的收益怎么归因？** 召回源打标，统计候选来自 MSM 的曝光、点击、收入、被下游保留比例、去重后净增量；不能只比"开/关 MSM"前后的整体 RPM。

## 10. 速查公式卡

```text
GSP CPC:        cpc_i = bid_{i+1} · qs_{i+1} / qs_i
eCPM:           pCTR · bid · 1000 (· quality_adj)
Pareto 支配:    A ≻ B iff ∀i A_i ≥ B_i ∧ ∃i A_i > B_i
Linear Scalar:  max Σ w_i · x_i (only convex frontier)
ε-Constraint:   max x_1 s.t. x_j ≥ ε_j ∀j≠1
Tchebycheff:    min max_i { λ_i · |x_i - x_i*| }
Degree Penalty: 1/log(1+deg), 1/sqrt(deg), idf
FTRL update:    w_{t+1} = argmin_w {Σg·w + L1 + L2}
GAUC:           Σ_u w_u · AUC_u / Σ_u w_u
CUPED:          Y_adj = Y - θ·(X - X̄)
RPM:            revenue / impressions × 1000
```
