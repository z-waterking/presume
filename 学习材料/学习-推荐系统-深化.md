## 1. 排序：从 LR 到 DIN，演进为什么这样发生

### 1.1 一条线讲清演进

```text
LR              :  线性 + 手工 cross；可解释、稀疏、训练快
GBDT + LR       :  GBDT 自动学交叉，LR 学稀疏；强基线
Wide & Deep     :  Wide 记忆强规则，Deep 泛化未见组合
DeepFM          :  把 wide 的人工 cross 替换成 FM 自动二阶
DCN / DCNv2     :  显式 bounded-degree cross，更稳更省样本
DIN             :  对 candidate 做 attention，从历史里抽相关兴趣
DIEN            :  GRU + AUGRU 建模兴趣演化
SIM / ETA       :  超长行为序列，先检索再 attend
```

每一代的"为什么换"：

- **LR → GBDT+LR**：手工 cross 维护成本高、覆盖差。
- **GBDT+LR → Wide&Deep**：树模型对稀疏 ID 泛化差。
- **Wide&Deep → DeepFM**：wide 部分人工特征仍贵。
- **DeepFM → DCNv2**：纯 DNN 高阶交叉训练样本利用率差，显式 cross 在样本不丰富时更稳。
- **DCN → DIN**：用户兴趣是"对当前候选有关的那部分"，全局 pooling 信息丢失。
- **DIN → DIEN**：兴趣会演化，序列建模更准。
- **DIEN → SIM**：行为序列上千条时 GRU 太慢，需要先 retrieve 再 attend。

### 1.2 必背的 4 个公式

**FM 二阶交叉**：

```text
ŷ(x) = w0 + Σ_i w_i x_i + Σ_{i<j} <v_i, v_j> x_i x_j
```

参数量 O(n·k)，比纯交叉项 O(n²) 小一个量级。

**DCN cross layer**：

```text
x_{l+1} = x_0 ⊙ (W_l x_l + b_l) + x_l
```

每一层显式做一次 bounded-degree cross，残差结构防止梯度消失。

**DIN attention**：

```text
v_user(candidate) = Σ_i a(e_i, e_cand) · e_i
a(·,·) = softmax over MLP-scored history
```

每个 candidate 看到的"用户向量"不一样。

**多目标融合分**：

```text
score = w_ctr · pCTR + w_cvr · pCVR · price + w_value · LTV + boost
```

注意各项量纲必须先校准（Platt / Isotonic）再加权。

## 2. 多目标：ESMM / MMoE / PLE 一次讲透

### 2.1 ESMM 解决 CVR 的样本选择偏差

样本选择偏差：CVR 训练只能在"曝光 ∩ 点击"的样本上做，但线上推理空间是全部曝光。
ESMM 在全空间联合建模：

```text
pCTR  = f_ctr(x)
pCTCVR = f_ctcvr(x) = pCTR · pCVR
loss = BCE(pCTR, y_click) + BCE(pCTCVR, y_buy)
```

`pCVR = pCTCVR / pCTR` 隐式得到，全样本参与训练。

### 2.2 MMoE / PLE：跷跷板效应

MMoE：多个 expert + 每个 task 独立 gate，task 之间共享 expert pool。
跷跷板效应：相关性低的 task 会争夺 expert，导致一升一降。
PLE：把 expert 分成"共享 expert + 任务专属 expert"，并在多层逐步分化。

讲法：
> MMoE 解决多目标共享表达，但 task 差异大时仍跷跷板。PLE 通过显式区分共享 / 专属 expert，并 progressive 分化，缓解跷跷板。

## 3. PID 调权：从控制论原理到上线 SOP

### 3.1 公式（带 anti-windup）

```text
e_t = target - measured_t
e_t_smooth = α · e_t + (1-α) · e_{t-1}_smooth        # 输入低通
P = Kp · e_t_smooth
I_raw = I_{t-1} + Ki · e_t_smooth · Δt
I = clamp(I_raw, I_min, I_max)                       # anti-windup
D = Kd · (e_t_smooth - e_{t-1}_smooth) / Δt
u_t = clip(P + I + D, -Δu_max, +Δu_max)              # 限幅
weight_{t+1} = clip(weight_t + u_t, w_min, w_max)
```

要点：

- **smoothing**：原始指标有噪声，必须先平滑。
- **anti-windup**：到边界后停止累积，否则 e 持续后会"积满"，等真正反向时反应迟钝。
- **rate limit**：每个 tick 变化幅度封顶，防止一次震荡把流量打穿。
- **deadband**：误差小于 ε 时不动作，避免对噪声追逐。

### 3.2 调节点选择（必背表）

| 调节点 | 响应 | 风险 | 适合场景 |
| ------ | ---- | ---- | -------- |
| Loss 权重 | 慢（小时-天） | 训练抖动 | 长期目标 |
| Score 融合权重 | 快（分钟） | 排序分布漂移 | 日级目标控制 ✅ 推荐 |
| Rerank quota | 快、可解释 | 表达力弱 | 活动 / 新品 / 类目保护 |

**默认讲法：调 score 融合权重**——响应快、可灰度、可回滚、不破坏模型本身。

### 3.3 PID vs RL vs Bandit

| 维度 | PID | Bandit | RL |
| ---- | --- | ------ | -- |
| 探索成本 | 几乎 0 | 低 | 高 |
| 可解释 | 强 | 中 | 弱 |
| 上线门槛 | 低 | 中 | 高 |
| 适合的目标 | 可观测连续指标 | arm 离散 | 长期回报 |

**面试一句话**：成熟电商业务对 GMV 和体验都有硬约束，不允许大规模无目的探索；PID 是最便宜也最稳的"小步闭环"。

### 3.4 安全机制（每条都背）

1. clipping（每 tick）+ rate limit（每 N tick）。
2. anti-windup（积分饱和保护）。
3. deadband（误差小不动）。
4. KL/PSI 监控分数分布漂移；超限自动 freeze。
5. AUC/GAUC 跌破阈值自动 rollback。
6. guardrail：CTR、投诉、延迟、CVR 任意越线触发降级。
7. kill switch：任何时候人工可一键回兜底权重。

## 4. 召回：多路召回 + Borda 融合

### 4.1 召回源对比表

| 召回源 | 信号 | 优点 | 风险 |
| ------ | ---- | ---- | ---- |
| I2I | item-item 共现 | 强相关 | 长尾覆盖差 |
| U2I | user-item 历史 | 个性化 | 冷启失效 |
| Two-tower | embedding 语义 | 泛化好 | 训练-服务一致性 |
| Graph (PinSage / PPR) | 图结构 | 多跳关系 | 计算重 |
| Hot / Trending | 全局热门 | 兜底 | 同质化 |
| Campaign / Rule | 业务约束 | 可控 | 与个性化冲突 |
| Multi-Interest (MIND) | 多兴趣向量 | 多样性 | 兴趣定义难 |

### 4.2 Borda Count 公式

```text
rank_score_s(item) = K - rank_s(item) + 1            # K 为该路 TopK
final(item) = Σ_s w_s · rank_score_s(item)
```

变种：

- **RRF**：`rank_score = 1 / (k + rank)`，强化头部。
- **Weighted Mean Reciprocal Rank**：偏头部稳定性。
- **Logistic-weighted Borda**：低 rank 衰减更快。

什么时候选哪个？
- 召回源很多、源质量差异大 → Borda（信息更丰富）。
- 头部最重要 / 抗噪 → RRF。
- 有充足训练数据 + 离线评估稳定 → Learning-to-fuse（GBDT/MLP）。

### 4.3 新召回源冷启动

1. 给小权重（如 base 的 10%），小流量灰度。
2. 监控：coverage、去重后曝光贡献、Hitrate、下游通过率、最终转化。
3. 至少 2 周稳定 + 一次 A/B 显著正向，才进入正常权重池。

### 4.4 Borda vs MLP 融合（30 秒口径）

> Borda 胜在零训练、零延迟、强可解释、对召回源上下线鲁棒；MLP 表达力强但需要大量稳定数据，召回源经常变化时维护成本高。我们把 Borda 当默认，少数高度稳定且数据丰富的场景上 learning-to-fuse。

## 5. 样本：延迟反馈 + 偏差

### 5.1 延迟反馈核心问题

电商转化常隔 1-7 天。把"当日未转化"标负 = fake negative。

解法：

- **归因窗口**：根据品类决定 24h / 72h / 7d。
- **缓存区 + 回填**：曝光后样本进 buffer，等窗口到再写 label。
- **DFM / ES-DFM**：建模延迟分布，对早期样本做加权或概率 label。

### 5.2 IPW 与 Doubly Robust

**IPW**：用倾向分 e(x) 给样本加权 1/e(x)，纠正选择偏差。
风险：e(x) 小的样本权重爆炸，方差高。

**Doubly Robust**：

```text
DR = E[ μ̂(x) + (y - μ̂(x)) · 1{a=π(x)} / e(x) ]
```

只要 μ̂ 或 e 有一个对，估计就无偏；方差比纯 IPW 低。

### 5.3 Position Bias：PAL

训练时把 position 作为单独 feature 进模型；推理时 position 设为 0（或最佳位置）。
这样 position 的影响被吸收到那一层，不会污染 item embedding。

## 6. 全链路解耦：Hitrate 高但线上不涨的 8 个原因（背全）

1. 命中的是精排原本就喜欢的旧分布，没增量。
2. 召回 item 被粗排或精排过滤，未到曝光。
3. Hitrate 正样本来自曝光日志，本身有 selection bias。
4. 召回扩大覆盖但相关性差，CTR/CVR 不升。
5. 召回源高度重叠，去重后净贡献小。
6. 离线评估窗口与线上流量分布不一致。
7. 长尾 / 新品 label 不足，被离线指标低估。
8. Hitrate@K 与 GMV/UV value 目标不一致。

### 6.1 上下游耦合的诊断方法

- 比较生产日志样本和探索流量样本的 item / category 分布。
- 看精排高分 item 在召回训练正样本中的占比是否异常高。
- 看某些召回源 Hitrate 高但去重后曝光贡献低。
- 看精排低估的 item 在探索流量里是否有更高真实转化。

## 7. A/B 实验：让收益可信

### 7.1 实验设计模板

| 维度 | 内容 |
| ---- | ---- |
| Primary | UV value / GMV / RPM |
| User guardrail | CTR、quick back、complaint |
| Advertiser guardrail | CPA / ROI / conv quality |
| Diagnostic | coverage / ad depth / dedup contribution |
| Quality diag. | relevance label、bad match rate |
| System | latency P95 / P99、超时率 |

### 7.2 CUPED 降方差

```text
Y_adj = Y - θ · (X - mean(X))
θ = Cov(Y, X) / Var(X)
```

X 是 pre-period 协变量。Y_adj 方差更低，相同样本量下显著性更高。

### 7.3 常见坑

- SRM（sample ratio mismatch）：分桶比例和预期偏差 > p<0.001 应停。
- Novelty effect：上线初期 CTR 升来自新鲜感，需 hold-out 看 4-8 周。
- Carryover：实验组用户被 treatment 影响后下个实验"残留"。
- Multi-test：同时跑多个 ��验，guardrail 互相影响。

## 8. 系统设计：5 分钟讲完电商首页推荐

1. 目标分层：点击、加购、成交、GMV、UV value、长期体验。
2. 召回：I2I / U2I / 双塔 / 图 / 热门 / 类目 / 新品探索 ≈ 10 路。

6. 重排：多样性、疲劳、业务规则、ε-探索。
7. 样本：延迟 label 缓存区、IPW、PAL、exploration traffic。
8. 实验：primary / guardrail / diagnostic、CUPED、分桶切片。

## 9. 项目复盘三段式（每个项目都用同一结构）

### 9.1 PID 排序

- **背景**：业务目标变化快，人工调权周期天级。
- **方案**：在 fine-rank score 融合权重上闭环 PID；P + I 为主，D 平滑。
- **难点**：噪声、延迟反馈、过冲、目标冲突。
- **保护**：clipping、anti-windup、KL/PSI、AUC、guardrail、kill switch。
- **结果**：UV value +12%。
- **边界**：PID 适合连续指标小步调，不适合无约束探索；目标冲突仍需业务对齐。

### 9.2 Borda 召回

- **背景**：10+ 路召回固定 TopK，低效源占坑。
- **方案**：Borda Count 按 rank 投票，source weight 由离线/在线闭环更新。
- **难点**：覆盖大但质量差的源、源间高度重叠、新源冷启。
- **保护**：权重上限、去重后贡献评估、互补性矩阵、灰度 ramp。
- **结果**：GMV +2.4%。
- **边界**：Rank 丢弃了原始置信度；高度稳定数据可上 learning-to-fuse。

### 9.3 全链路解耦

- **背景**：召回正样本来自精排胜出日志，马太效应。
- **方案**：探索流量 + 修正 label + 召回源泛化。
- **难点**：探索流量有体验成本，离线 / 在线指标可能冲突。
- **保护**：低比例、白名单场景、guardrail、自动回滚。
- **结果**：诊断能力提升，长尾 item 转化 +X%。
- **边界**：探索流量也不完全无偏，需要持续校正。

## 10. 高频追问的标准答案段（背 6 段）

1. **多目标冲突怎么办？** 主目标进 PID error，体验类做 hard guardrail，商业类做 soft constraint；冲突无法消除时，业务定优先级，PID 只在边界内动。

2. **Hitrate 高但线上不涨？** 8 大原因（见第 6 节），现场按"是否有增量、是否被过滤、是否有偏、是否相关、是否重叠、窗口、长尾、目标对齐"逐项查。

3. **新召回源冷启？** 小权重 + 灰度 + 多维度 diagnostic + 至少一次 A/B 显著正向才进权重池。

4. **延迟反馈怎么处理？** 归因窗口（按品类） + 缓存区回填 + ES-DFM；fake negative 是首要风险。

5. **粗排 vs 精排？** 候选数量、特征数量、模型复杂度三层差异；粗排通过蒸馏与精排对齐，避免"粗排砍掉精排会喜欢的"。

6. **冷启动？** 内容特征 + bandit / Thompson Sampling + 类目 prior + exploration quota；不能完全依赖个性化模型。

## 11. 速查公式卡

```text
PID:           u = Kp·e + Ki·∫e dt + Kd·de/dt
FM:            ŷ = w0 + Σwx + ΣΣ <v_i,v_j> x_i x_j
DCN cross:     x_{l+1} = x_0 ⊙ (W x_l + b) + x_l
DIN attn:      v_u(c) = Σ_i softmax(MLP(e_i,e_c)) · e_i
ESMM:          pCTCVR = pCTR · pCVR
Borda:         Σ_s w_s · (K - rank_s(item) + 1)
RRF:           Σ_s 1 / (k + rank_s(item))
IPW:           Σ y_i / e(x_i)
DR:            μ̂(x) + (y - μ̂(x))·1{a=π(x)}/e(x)
CUPED:         Y_adj = Y - θ·(X - X̄), θ=Cov(Y,X)/Var(X)
NDCG@K:        DCG@K / IDCG@K, DCG = Σ (2^rel - 1)/log2(rank+1)
Hitrate@K:     #users w/ pos in topK / #users
```
