## 1. 多目标排序 / LTR / PID 控制

### 多目标排序论文

- [ ] [ESMM: Entire Space Multi-Task Model](https://arxiv.org/abs/1804.07931) — 阿里妈妈, SIGIR 2018。多目标排序开山之作，解决 CVR 样本选择偏差
- [ ] [MMoE: Multi-gate Mixture-of-Experts](https://dl.acm.org/doi/10.1145/3219819.3220007) — Google, KDD 2018。多目标排序最经典网络结构，**面试必问**
- [ ] [PLE: Progressive Layered Extraction](https://dl.acm.org/doi/10.1145/3383313.3412236) — 腾讯, RecSys 2020。解决 MMoE 跷跷板问题
- [ ] [Controllable Multi-Objective Re-ranking](https://arxiv.org/abs/2307.09526) — 阿里。PID 控制器动态调权，和你核心经验直接对应
- [ ] [From RankNet to LambdaRank to LambdaMART](https://www.microsoft.com/en-us/research/publication/from-ranknet-to-lambdarank-to-lambdamart-an-overview/) — MSR, 2010。LTR 三大范式最经典综述
- [ ] [Personalized Re-ranking](https://arxiv.org/abs/1904.06813) — 阿里, RecSys 2019。重排序阶段个性化
- [ ] [Pareto-Optimal Multi-Objective 综述](https://arxiv.org/abs/2108.04690) — Pareto 最优理论基础

### 多目标关键词自测

> LTR 三大范式: Pointwise / Pairwise (RankNet, LambdaRank) / Listwise (LambdaMART)
> 多目标建模: ESMM / MMoE / PLE / DBMTL / Seesaw Effect
> 多目标融合: `score = w1*pCTR + w2*pCVR*price` / 动态调权 / 约束优化
> PID 控制器: 比例-积分-微分 / 在线动态调整目标权重 / 保底约束
> 深度排序模型演进: LR → GBDT+LR → Wide&Deep → DeepFM → DIN → DIEN → SIM
> Calibration: Platt Scaling / Isotonic Regression
> Position Bias: PAL / 训练加 Position 特征, 推理去掉

## 7. 深化阅读地图：按你的简历反推

> 目标不是泛泛学推荐系统，而是让阿里三段经历都能被追问到论文、指标、工程权衡和系统设计。

### 7.1 排序与多目标控制：支撑「深度控制 LTR / PID」

- [ ] [DIN: Deep Interest Network](https://arxiv.org/abs/1706.06978) — 阿里 KDD 2018。用户行为序列注意力，补齐「电商排序模型」背景。
- [ ] [DIEN: Deep Interest Evolution Network](https://arxiv.org/abs/1809.03672) — 阿里 AAAI 2019。兴趣演化建模，面试可用来解释短期/长期兴趣漂移。
- [ ] [SIM: Search-based Interest Model](https://arxiv.org/abs/2006.05639) — 阿里 CIKM 2020。超长行为序列建模，和海外电商大规模行为序列强相关。
- [ ] [Wide & Deep](https://arxiv.org/abs/1606.07792) — Google 2016。记忆与泛化的经典框架，推荐/广告排序都能用。
- [ ] [DeepFM](https://arxiv.org/abs/1703.04247) — IJCAI 2017。FM 特征交叉 + DNN 表达能力，解释 CTR/CVR 排序基础。
- [ ] [DCN V2](https://arxiv.org/abs/2008.13535) — Google WWW 2021。显式特征交叉，适合补「为什么某些模型比纯 DNN 更稳」。
- [ ] [Feedback Control for Computer Systems](https://www.oreilly.com/library/view/feedback-control-for/9781449361709/) — 控制论工程书。用来把 PID 讲得像工程系统，而不是只讲公式。
- [ ] [PID Controller Approach for Stochastic Optimization](https://arxiv.org/abs/1802.06138) — 从优化角度理解 PID，可作为「为什么 PID 能做动态调权」的数学补充。

读完要能回答：

- PID 调的是 Loss 权重、Score 权重还是业务策略阈值？为什么这个调节点最稳？
- 多目标排序里 pCTR、pCVR、GMV、UV value 量纲不同，怎么归一化和校准？
- PID 和 Bandit/RL 比，为什么在成熟电商业务里更容易上线？
- 如果目标之间冲突，例如 GMV 升但用户体验降，如何设计 guardrail？

### 7.2 召回、多兴趣与多路融合：支撑「Borda Count 动态融合」

- [ ] [MIND: Multi-Interest Network with Dynamic Routing](https://arxiv.org/abs/1904.08030) — 阿里 CIKM 2019。一个用户多个兴趣向量，适合解释「召回多样性」。
- [ ] [ComiRec: Controllable Multi-Interest Framework](https://arxiv.org/abs/2005.09347) — KDD 2020。可控多兴趣召回，补「为什么固定 TopK 不够」。
- [ ] [TDM: Learning Tree-based Deep Model for Recommender Systems](https://arxiv.org/abs/1801.02294) — 阿里。树检索召回，适合和双塔/ANN 对比。
- [ ] [PinSage](https://arxiv.org/abs/1806.01973) — Pinterest KDD 2018。图卷积用于大规模推荐召回。
- [ ] [Pixie: Random Walks on Pinterest Graph](https://dl.acm.org/doi/10.1145/3219819.3219846) — KDD 2018。图召回工业实践，能和 Query-Ad/Item graph 类问题串起来。
- [ ] [Reciprocal Rank Fusion](https://plg.uwaterloo.ca/~gvcormac/cormacksigir09-rrf.pdf) — RRF 排名融合。和 Borda Count 对比：Borda 用线性名次分，RRF 强化头部稳定性。
- [ ] [Microsoft Recommenders](https://github.com/recommenders-team/recommenders) — 工业推荐算法样例库，可快速复现召回、排序、评估指标。
- [ ] [RecBole](https://github.com/RUCAIBox/RecBole) — 推荐系统实验框架，适合看不同召回/排序模型的统一训练评估方式。

读完要能回答：

- 多路召回融合为什么不能直接加原始分？Rank 融合损失了哪些信息？
- Borda Count、RRF、归一化加权、Learning-to-rank 融合分别适合什么场景？
- 召回源经常上下线时，为什么简单、可解释、低延迟的方法反而更有工程价值？
- 如果某一路召回覆盖很广但转化差，权重该怎么下降？看 Hitrate 还是看最终转化？

### 7.3 样本偏差、延迟反馈、全链路解耦：支撑「全链路评估」

- [ ] [Counterfactual Learning and Evaluation for Recommender Systems](https://dl.acm.org/doi/10.1145/3240323.3240355) — 反事实评估，理解线上日志有偏时怎么离线评估。
- [ ] [Doubly Robust Off-policy Evaluation](https://arxiv.org/abs/1103.4601) — DR 估计基础，补充 IPW 的高方差问题。
- [ ] [A/B Testing Intuition Busters](https://www.exp-platform.com/Documents/2017-08%20ABTestingIntuitionBusters.pdf) — Kohavi。解释线上实验常见坑，回答「收益怎么验证」。
- [ ] [Trustworthy Online Controlled Experiments](https://experimentguide.com/) — A/B 实验系统性材料，适合准备指标显著性、guardrail、novelty effect。
- [ ] [Feast Feature Store](https://docs.feast.dev/) — 特征平台参考，补「实时/离线特征一致性」和训练服务一致性。
- [ ] [Flink Stateful Stream Processing](https://nightlies.apache.org/flink/flink-docs-stable/docs/concepts/stateful-stream-processing/) — 延迟 Label、缓存区、回填都可以映射到状态流处理。

读完要能回答：

- 精排胜出日志为什么会让召回训练有偏？这个偏差属于 selection bias 还是 position bias？
- Exploration Traffic 比随机打散全量流量更安全在哪里？如何控制流量成本？
- 延迟 Label 归因窗口选 24h、72h、7d 的取舍是什么？
- 在线 A/B 收益和离线 Hitrate 冲突时，优先相信哪个？下一步怎么诊断？

## 8. 面试追问题库升级

### PID / 多目标排序

- Q: PID 的 error 是单指标还是多指标？多指标 error 怎么合成？
- Q: 积分项会不会导致 wind-up？怎么做 anti-windup？
- Q: 为什么不直接重训模型，而是调后链路权重？
- Q: 线上指标有噪声和延迟，PID 输入怎么平滑？
- Q: 如果 UV value +12% 但 GMV 没涨，业务怎么解释？

### Borda / 多路召回融合

- Q: Borda Count 是否会偏向覆盖率高的召回源？如何惩罚低质量大覆盖源？
- Q: 新召回源冷启动没有历史权重，怎么接入？
- Q: Borda 融合后如何保证多样性、去重和类目约束？
- Q: 如果两个召回源高度重叠，是保留二者还是合并？怎么评估互补性？

### 全链路 / 无偏评估

- Q: Hitrate 高但线上不涨，可能有哪些原因？
- Q: 召回与精排耦合怎么用数据证明？
- Q: 随机探索流量会伤害用户体验，如何设置保护阈值？
- Q: 粗排、精排、重排之间的目标不一致怎么处理？
