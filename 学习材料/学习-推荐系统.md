## 12. 公式与概念卡

### PID 动态调权

```text
error_t = target_t - observed_t
P_t = Kp * error_t
I_t = Ki * clamp(sum(error_i), lower, upper)
D_t = Kd * smooth(error_t - error_{t-1})
control_t = clip(P_t + I_t + D_t, -max_delta, max_delta)
```

面试解释：

- P 解决当前偏差，反应快。
- I 解决长期偏差，但容易 wind-up。
- D 预测趋势，但对噪声敏感，通常要平滑。
- 在线系统重点不是公式，而是 clipping、anti-windup、guardrail、rollback。

### 多目标排序分数

```text
score = w_ctr * pCTR
      + w_cvr * pCVR * price
      + w_value * long_term_value
      + w_rule * business_boost
```

风险：

- 各项量纲不同，必须校准或归一化。
- 短期 GMV 可能伤害长期留存。
- 业务 boost 需要上限，避免破坏模型排序。

### Borda Count

```text
rank_score_s(item) = K - rank_s(item) + 1
final_score(item) = sum_s source_weight_s * rank_score_s(item)
```

面试解释：

- Rank 融合解决分数尺度不同。
- Source weight 解决召回源质量不同。
- 去重、类目约束、多样性通常在融合后或重排阶段处理。

### Hitrate@K

```text
Hitrate@K = users_with_positive_item_in_topK / total_users
```

注意：

- Hitrate 是召回能力指标，不等于最终 GMV。
- 如果正样本来自精排曝光日志，Hitrate 本身会带精排偏见。
- 要结合 coverage、增量转化、下游通过率、探索样本看。

### 延迟反馈

```text
label_at_day0 = unknown, not negative
label_after_window = converted ? positive : negative
```

解释：

- 电商转化有时间延迟，当天未买不代表不喜欢。
- 过短窗口制造 fake negative，过长窗口降低训练新鲜度。

## 13. 阿里推荐系统设计模板

### 离线/近线/在线分层

| 层级 | 内容 | 关键点 |
| ---- | ---- | ------ |
| 离线 | 样本构造、特征回填、模型训练、召回索引 | 数据完整、训练稳定、可复现 |
| 近线 | 实时行为、增量特征、向量更新、规则配置 | 新鲜度、延迟、幂等 |
| 在线 | 召回、粗排、精排、重排、实验分桶 | 延迟、稳定、降级 |
| 监控 | 指标、分布、延迟、异常、A/B | 及时发现坏实验 |

### 推荐首页 5 分钟答案

1. 先定义目标：点击、加购、成交、GMV、UV value、长期体验。
2. 召回层多路生成：I2I、U2I、双塔、热门、类目、活动、新品探索。
3. 融合层用 Borda/RRF/配额策略控制召回源贡献和多样性。
4. 粗排用轻量模型筛到千级，精排用深模型打分。
5. 重排处理多样性、去重、疲劳、业务规则和探索。
6. 样本层处理延迟反馈、position bias、selection bias。
7. 实验层看 primary、guardrail、diagnostic，分场景切片。
8. 监控层看模型分布、特征缺失、召回量、延迟、回滚。

## 14. 项目复盘模板

### PID 排序复盘

- 背景：目标变化快，人工调权慢。
- 方案：把后链路 score/loss 权重做成闭环控制。
- 难点：指标噪声、延迟反馈、过冲、目标冲突。
- 保护：clipping、anti-windup、KL、AUC、A/B guardrail。
- 结果：UV value +12%。
- 边界：PID 适合小步稳定调控，不适合无约束探索。

### Borda 召回复盘

- 背景：多路召回固定 TopK，低效源占坑。
- 方案：按 rank 投票融合，source weight 由离线/在线评估闭环更新。
- 难点：召回源分数不可比、覆盖大但质量差、源间重叠。
- 保护：权重上限、去重后贡献、增量转化、探索接入。
- 结果：GMV +2.4%。
- 边界：Borda 简单稳，但不能表达复杂 item/source 交互。

### 全链路解耦复盘

- 背景：召回训练样本来自精排胜出日志，容易形成选择偏差。
- 方案：Hitrate 诊断 + exploration traffic + 召回来源泛化。
- 难点：探索流量有成本，离线指标和线上收益可能冲突。
- 保护：小流量、场景白名单、体验 guardrail、逐步 ramp。
- 结果：提升对召回真实增量的判断能力。
- 边界：探索数据也不是完全无偏，需要持续校正。
