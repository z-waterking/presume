## 1. 多目标排序 / LTR / PID 控制

### 多目标排序论文

- [ ] [ESMM: Entire Space Multi-Task Model](https://arxiv.org/abs/1804.07931) — 阿里妈妈, SIGIR 2018。多目标排序开山之作。
  - 核心内容：把 CTR 和 CTCVR 放在全样本空间联合建模，通过 `pCTCVR = pCTR * pCVR` 间接学习 CVR，缓解只在点击样本上训练 CVR 的 sample selection bias。
  - 业务直觉：曝光未点击样本也提供“没有转化”的信息，不能只用点击后样本训练转化模型。
  - 和简历连接：你做延迟反馈、样本缓存和全链路解耦时，核心问题也是 label 空间和样本偏差。
  - 面试口径：ESMM 说明推荐/广告多目标不是简单多头输出，关键是定义正确样本空间和目标依赖关系。
  - 风险边界：ESMM 解决点击选择偏差的一部分，但不自动解决延迟反馈、位置偏差和精排胜出日志偏差。
- [ ] [MMoE: Multi-gate Mixture-of-Experts](https://dl.acm.org/doi/10.1145/3219819.3220007) — Google, KDD 2018。多目标排序经典结构。
  - 核心内容：多个 expert 共享底层表示，不同任务通过各自 gate 组合 expert，兼顾共享和任务差异。
  - 解决问题：多任务之间有相关性但不完全一致，硬共享会互相干扰，完全分开又浪费数据。
  - 和简历连接：阿里排序里 pCTR、pCVR、GMV、UV value、加购等目标可能冲突，MMoE 是多目标建模基础。
  - 面试口径：MMoE 解决模型结构层面的多目标共享，PID 解决线上业务目标权重随时间变化的问题，二者层次不同。
  - 风险边界：MMoE 仍可能有 seesaw effect，一个目标提升另一个下降，需要 PLE、动态权重或 guardrail。
- [ ] [PLE: Progressive Layered Extraction](https://dl.acm.org/doi/10.1145/3383313.3412236) — 腾讯, RecSys 2020。解决 MMoE 跷跷板问题。
  - 核心内容：把 shared experts 和 task-specific experts 分层抽取，逐步分离共享信息和任务特有信息。
  - 解决问题：MMoE 共享过强时任务互相拉扯，PLE 更明确地隔离任务冲突。
  - 和简历连接：当业务目标冲突明显，例如 GMV、点击、体验、新品扶持同时存在时，PLE 是模型结构层面的解法。
  - 面试口径：PLE 是训练阶段的多任务结构，PID 是上线后的控制策略；成熟系统常常两者都需要。
  - 风险边界：结构复杂会增加训练和调参成本，线上收益仍要靠 A/B 和 guardrail 验证。
- [ ] [Controllable Multi-Objective Re-ranking](https://arxiv.org/abs/2307.09526) — 阿里。PID 控制器动态调权，和你核心经验直接对应。
  - 核心内容：把多目标推荐重排建成可控系统，通过控制器调节目标权重，让线上指标向业务目标靠拢。
  - PID 直觉：P 处理当前偏差，I 处理长期偏差，D 处理变化趋势，输出影响排序权重或重排策略。
  - 和简历连接：你的“实时深度控制模块 / PID 动态调整 Loss 或 Ranking Score 权重”可以用这篇做理论背书。
  - 面试口径：PID 不是替代排序模型，而是在模型输出之上增加业务目标闭环控制，适合大促、新品、场景切换等目标变化快的情况。
  - 风险边界：控制器一定要有 clipping、anti-windup、指标平滑、回滚和体验 guardrail，否则会过冲。
- [ ] [From RankNet to LambdaRank to LambdaMART](https://www.microsoft.com/en-us/research/publication/from-ranknet-to-lambdarank-to-lambdamart-an-overview/) — MSR, 2010。LTR 三大范式综述。
  - 核心内容：RankNet 用 pairwise loss 学排序，LambdaRank 用 NDCG 变化构造 lambda 梯度，LambdaMART 用 boosted trees 做强排序模型。
  - 和推荐连接：推荐排序不是只预测点击率，也要优化列表顺序和位置敏感指标。
  - 和简历连接：你可以用它解释 LTR 后链路的基础，再引出为什么业务目标变化后需要动态调权。
  - 面试口径：Pointwise 预测概率，pairwise 学相对顺序，listwise 更贴近最终列表指标；工业系统常按数据规模和延迟折中。
  - 风险边界：离线 LTR 指标提升不一定线上 GMV/UV value 提升，仍要看实验和业务目标。
- [ ] [Personalized Re-ranking](https://arxiv.org/abs/1904.06813) — 阿里, RecSys 2019。重排序阶段个性化。
  - 核心内容：在精排之后通过重排考虑用户个性化、多样性、上下文和列表整体效果。
  - 和简历连接：PID 调权也常落在后链路或重排阶段，因为这里响应快、可控、易灰度。
  - 面试口径：精排给 item 级分数，重排处理列表级约束和业务控制；我的 PID 更像在后链路调节最终目标。
  - 风险边界：重排过强会破坏精排分布，需要 KL/PSI、CTR/CVR guardrail 和回滚。
- [ ] [Pareto-Optimal Multi-Objective 综述](https://arxiv.org/abs/2108.04690) — Pareto 最优理论基础。
  - 核心内容：多目标问题中，一个解如果不能在不损害其他目标的情况下改进某个目标，就处在 Pareto frontier。
  - 和推荐连接：GMV、点击、转化、留存、体验、新品扶持经常互相冲突，不存在单一最优。
  - 和简历连接：可用于解释 PID / 约束优化 / guardrail 背后的多目标权衡思想。
  - 面试口径：业务不是单纯最大化 GMV，而是在多个目标和硬约束下找可接受的 trade-off。
  - 风险边界：Pareto 是决策框架，不会自动告诉你业务偏好；权重和约束仍需业务定义。

### 多目标关键词自测

> LTR 三大范式: Pointwise / Pairwise (RankNet, LambdaRank) / Listwise (LambdaMART)
> 多目标建模: ESMM / MMoE / PLE / DBMTL / Seesaw Effect
> 多目标融合: `score = w1*pCTR + w2*pCVR*price` / 动态调权 / 约束优化
> PID 控制器: 比例-积分-微分 / 在线动态调整目标权重 / 保底约束
> 深度排序模型演进: LR → GBDT+LR → Wide&Deep → DeepFM → DIN → DIEN → SIM
> Calibration: Platt Scaling / Isotonic Regression
> Position Bias: PAL / 训练加 Position 特征, 推理去掉

## 2. 多路召回融合 / 召回评估

### 召回论文

- [ ] [YouTube Recommendations DNN](https://dl.acm.org/doi/10.1145/2959100.2959190) — Google, RecSys 2016。⭐ **面试必读 No.1**。
  - 核心内容：两阶段推荐架构，candidate generation 从海量视频召回几百个候选，ranking 再精细排序。
  - 召回阶段：把推荐建成极大规模多分类问题，用用户历史、上下文和 video embedding 召回候选。
  - 排序阶段：用更丰富特征预测 expected watch time 等目标。
  - 和简历连接：阿里推荐同样是召回-排序漏斗，Borda 融合发生在 candidate generation 后的多路召回合并。
  - 面试口径：YouTube DNN 是工业推荐两阶段架构模板，解释了为什么召回重覆盖和效率，排序重精细特征和目标。
  - 风险边界：召回离线命中高不等于最终收益高，下游排序、重排和样本偏差会改变结果。
- [ ] [EBR: Facebook Embedding-based Retrieval](https://arxiv.org/abs/2006.11632) — Meta, KDD 2020。工业级向量召回。
  - 核心内容：用 embedding 检索替代一部分规则/倒排召回，解决大规模候选生成和兴趣泛化。
  - 工程要点：向量训练、ANN 索引、召回新鲜度、线上延迟、索引更新和召回质量评估。
  - 和简历连接：你的多路召回融合里，Embedding 召回通常是其中一路，和 I2I、U2I、热门、规则召回一起融合。
  - 面试口径：Embedding 召回覆盖强但质量波动，需要 Borda/source weight 和 Hitrate/转化评估控制贡献。
  - 风险边界：向量相似可能带来同质化和热门偏置，也可能缺少可解释性。
- [ ] [Sampling-Bias-Corrected Neural Modeling](https://dl.acm.org/doi/10.1145/3298689.3346996) — Google, RecSys 2019。双塔采样纠偏。
  - 核心内容：在 sampled softmax / negative sampling 训练中修正采样分布和真实分布不一致带来的偏差。
  - 和召回连接：双塔召回通常无法对全量 item 做 softmax，只能采样负例；采样方式会影响模型学到的概率和排序。
  - 和简历连接：你做召回评估和全链路解耦时，可以延伸到“召回训练数据和线上分布不一致”的问题。
  - 面试口径：召回模型不只是结构问题，负采样和样本分布会直接影响候选质量。
  - 风险边界：纠偏公式不能替代线上实验，离线采样假设和线上曝光机制仍可能不一致。
- [ ] [PDN: Multi-Channel Recall](https://arxiv.org/abs/2105.08571) — 阿里, 2021。多路召回融合。
  - 核心内容：面向多通道召回建模不同召回源的贡献与互补性，而不是简单固定配额。
  - 和简历连接：你的 Borda Count 是一种工程上更简单、低延迟、可解释的多路召回融合方式。
  - 面试口径：学习式融合表达能力强，但召回源频繁上下线、延迟严格时，Borda/RRF 这类 rank fusion 更容易维护。
  - 风险边界：Borda 简单稳定，但无法表达复杂 source-item-user 交互；后续可升级为学习式融合。
- [ ] [Deep Retrieval](https://arxiv.org/abs/2007.07203) — 字节, 2020。端到端召回。
  - 核心内容：尝试直接从用户行为到 item 候选做深度检索，减少人工召回策略。
  - 和简历连接：提供“为什么不完全端到端”的反面讨论：你的系统选择多路召回 + Borda，是为了可解释、可控、易接入新源。
  - 面试口径：端到端召回有潜力，但成熟业务里多路召回仍有价值，因为不同源覆盖不同人群、场景和业务目标。
  - 风险边界：端到端模型难解释、冷启动和业务规则接入成本高，线上风险更大。

### 召回关键词自测

> 多路召回: CF / 热门 / 标签 / Embedding / 图 / 行为序列
> 双塔 Two-Tower: 用户塔+物品塔 / ANN / FAISS / ScaNN
> 负采样: In-batch Negatives / Hard Negative Mining
> 多路融合: Borda Count / RRF / 分数归一化
> Hitrate 评估: 各路命中率对比 / UV转化率 / 与精排一致性

## 3. 样本构造 / 延迟反馈 / 无偏学习

### 样本论文

- [ ] [Modeling Delayed Feedback](https://dl.acm.org/doi/10.1145/2623330.2623634) — Chapelle, KDD 2014。延迟反馈开山论文。
  - 核心内容：转化不是曝光后立即发生，负样本可能只是“还没转化”，直接标负会制造 fake negative。
  - 和电商连接：用户从浏览到购买可能隔数小时到数天，品类越重决策周期越长。
  - 和简历连接：你的样本缓存区、归因窗口、延迟 label 回填都可以用这篇解释。
  - 面试口径：延迟反馈的关键是把 unknown 和 negative 区分开，不能当天未买就当永久负样本。
  - 风险边界：窗口太短会假负，窗口太长会降低训练新鲜度，需要按品类和业务目标权衡。
- [ ] [ES-DFM](https://arxiv.org/abs/2104.01160) — 阿里, AAAI 2021。Elapsed-Time 建模转化延迟。
  - 核心内容：把 elapsed time 纳入延迟反馈建模，同时考虑转化概率和转化发生时间。
  - 和简历连接：海外电商不同市场、物流、价格带会影响转化周期，elapsed-time 视角很贴合。
  - 面试口径：解决延迟反馈不能只靠固定窗口，也可以建模“多久后还没转化才更像负样本”。
  - 风险边界：模型更复杂，需要可靠转化回传和归因数据。
- [ ] [Unbiased Learning to Rank](https://arxiv.org/abs/1804.05938) — SIGIR 2018。IPW 消除位置偏差。
  - 核心内容：用户更可能点击靠前位置，点击日志混合了相关性和曝光位置；IPW 用 propensity 反向加权纠偏。
  - 和简历连接：你研究召回与精排耦合，本质也在处理日志偏差；position bias 是其中经典类型。
  - 面试口径：线上日志不是自然标签，必须问“为什么这个 item 被看见”，否则模型会学习曝光机制而不是真实偏好。
  - 风险边界：IPW 容易高方差，propensity 估不准会带来新偏差。
- [ ] [PAL: Position-bias Aware Learning](https://dl.acm.org/doi/10.1145/3298689.3347033) — 华为, RecSys 2019。
  - 核心内容：显式建模 position bias，让模型区分 item relevance 和位置带来的点击倾向。
  - 和简历连接：解释“训练加 position 特征、推理去 position 特征”的思想，避免模型线上只学位置。
  - 面试口径：位置偏差纠正的目标是让排序模型学 item/user 真实相关性，而不是复制历史展示位置。
  - 风险边界：位置只是偏差之一，精排胜出日志还包含 selection bias 和 feedback loop。

### 样本关键词自测

> 样本构造: 曝光点击=正 / 曝光未点击=负 / 全空间样本
> 延迟反馈: 归因窗口 / Fake Negative / DFM / ES-DFM
> 无偏学习: IPW / Doubly Robust / Selection Bias
> Exploration: ε-greedy / Thompson Sampling / EE权衡

## 4. 粗排 / 蒸馏 / 全链路架构

### 全链路论文

- [ ] [COLD: 阿里粗排](https://arxiv.org/abs/2007.16122) — DLP-KDD 2020。蒸馏到粗排。
  - 核心内容：把精排/复杂模型中的知识蒸馏到粗排阶段，让粗排更接近精排目标，同时控制延迟。
  - 和简历连接：你的 Drop Rank 和 Top 10% 特征蒸馏可以用 COLD 解释“把复杂特征/模型能力迁移到轻量链路”。
  - 面试口径：粗排不是简单弱模型，它要在千级候选中尽量保住精排会喜欢的 item。
  - 风险边界：过度对齐精排会放大精排偏见，仍要保留探索和多样性。
- [ ] [Privileged Features Distillation](https://arxiv.org/abs/2007.07646) — 阿里, KDD 2020。
  - 核心内容：训练时使用线上不可用或成本太高的 privileged features，通过蒸馏让轻量模型学习其信息。
  - 和简历连接：Top 10% 特征蒸馏正是“离线大特征帮助线上轻模型”的思想。
  - 面试口径：蒸馏解决效果和延迟的矛盾，让昂贵特征在训练期发挥作用，服务期保持轻量。
  - 风险边界：teacher 偏差会传给 student，且蒸馏目标要和线上业务指标一致。
- [ ] [Monolith](https://arxiv.org/abs/2209.07663) — 字节, 2022。实时训练架构。
  - 核心内容：面向推荐系统的实时训练/在线学习架构，处理大规模稀疏 ID、新鲜行为和分布漂移。
  - 和简历连接：海外电商场景变化快，实时/近线特征和样本回流会影响 PID 控制和排序稳定性。
  - 面试口径：推荐系统效果不只来自模型结构，也来自样本、特征、训练和服务的实时闭环。
  - 风险边界：实时训练要求强监控，否则错误数据会快速污染模型。

### 全链路关键词自测

> 四级漏斗: 召回(万级) → 粗排(千级) → 精排(百级) → 重排
> 蒸馏: Teacher-Student / Soft Label / Privileged Features
> Drop Rank: 去掉某特征后排序变化 → 特征重要度

> 目标不是泛泛学推荐系统，而是让阿里三段经历都能被追问到论文、指标、工程权衡和系统设计。

### 7.1 排序与多目标控制：支撑「深度控制 LTR / PID」

- [ ] [DIN: Deep Interest Network](https://arxiv.org/abs/1706.06978) — 阿里 KDD 2018。用户行为序列注意力。
  - 核心内容：对用户历史行为按候选 item 做 attention，动态提取和当前候选相关的兴趣。
  - 和简历连接：AE 电商排序需要理解用户短期兴趣，例如最近看鞋和现在候选鞋更相关。
  - 面试口径：DIN 说明排序模型要做 candidate-aware interest，而不是把用户历史简单平均。
  - 风险边界：行为序列噪声、冷启动和延迟特征会影响 attention 质量。
- [ ] [DIEN: Deep Interest Evolution Network](https://arxiv.org/abs/1809.03672) — 阿里 AAAI 2019。兴趣演化建模。
  - 核心内容：在 DIN 基础上建模用户兴趣随时间演化，用序列结构捕捉兴趣迁移。
  - 和简历连接：海外电商用户兴趣会受季节、促销、物流周期影响，短期/长期兴趣都重要。
  - 面试口径：DIEN 从“当前候选相关兴趣”进一步走到“兴趣如何演化”。
  - 风险边界：序列模型更重，对实时性和特征完整性要求更高。
- [ ] [SIM: Search-based Interest Model](https://arxiv.org/abs/2006.05639) — 阿里 CIKM 2020。超长行为序列建模。
  - 核心内容：先从超长历史中检索和候选相关的行为，再做精细兴趣建模。
  - 和简历连接：海外电商用户行为长且稀疏，不能把所有历史都喂给模型，需要先检索相关兴趣。
  - 面试口径：SIM 的思想是“先召回用户历史中的相关片段，再排序”，和系统漏斗思想一致。
  - 风险边界：历史检索本身会引入召回偏差，需要监控覆盖和新鲜度。
- [ ] [Wide & Deep](https://arxiv.org/abs/1606.07792) — Google 2016。记忆与泛化的经典框架。
  - 核心内容：Wide 记忆高频规则和交叉，Deep 泛化到未见组合。
  - 和推荐连接：电商既有强规则，如类目/品牌/价格带，也有长尾泛化需求。
  - 面试口径：排序系统要平衡 memorization 和 generalization，业务规则不能完全交给 deep model 黑盒。
  - 风险边界：wide 特征维护成本高，deep 泛化需要 guardrail。
- [ ] [DeepFM](https://arxiv.org/abs/1703.04247) — IJCAI 2017。FM 特征交叉 + DNN。
  - 核心内容：FM 学低阶交叉，DNN 学高阶交叉，共享 embedding。
  - 和简历连接：LTR 排序中的用户、item、场景、价格、活动等特征大量需要交叉。
  - 面试口径：DeepFM 是 CTR/CVR 排序基础模型之一，可以作为轻量排序基线。
  - 风险边界：特征穿越和训练服务不一致会让离线指标虚高。
- [ ] [DCN V2](https://arxiv.org/abs/2008.13535) — Google WWW 2021。显式特征交叉。
  - 核心内容：通过 cross network 学显式 bounded-degree feature crosses，增强可控交叉表达。
  - 和简历连接：解释为什么某些业务交叉，如场景×类目×价格带，不能只依赖普通 DNN 自己学。
  - 面试口径：DCN 类模型适合高维稀疏推荐/广告特征，能提升样本效率和稳定性。
  - 风险边界：交叉过多会过拟合，需要正则和特征筛选。
- [ ] [Feedback Control for Computer Systems](https://www.oreilly.com/library/view/feedback-control-for/9781449361709/) — 控制论工程书。
  - 核心内容：把计算机系统看成带反馈的动态系统，关注目标、误差、控制器、稳定性和响应速度。
  - 和简历连接：帮你把 PID 讲成“闭环控制系统”，而不是简单套公式。
  - 面试口径：推荐排序调权本质是控制问题：目标值、观测值、误差、控制动作、反馈延迟和稳定性。
  - 风险边界：控制器只在系统可观测、可调节、反馈可靠时有效。
- [ ] [PID Controller Approach for Stochastic Optimization](https://arxiv.org/abs/1802.06138) — 从优化角度理解 PID。
  - 核心内容：把 PID 与随机优化、梯度更新联系起来，解释 P/I/D 对收敛和稳定性的影响。
  - 和简历连接：为“为什么 PID 能用于动态调权”提供更数学化解释。
  - 面试口径：PID 不只是传统控制，也可以理解为对 noisy online metric 的稳定更新策略。
  - 风险边界：理论优化视角不能替代线上 guardrail，推荐系统指标延迟和噪声更复杂。

读完要能回答：

- PID 调的是 Loss 权重、Score 权重还是业务策略阈值？为什么这个调节点最稳？
- 多目标排序里 pCTR、pCVR、GMV、UV value 量纲不同，怎么归一化和校准？
- PID 和 Bandit/RL 比，为什么在成熟电商业务里更容易上线？
- 如果目标之间冲突，例如 GMV 升但用户体验降，如何设计 guardrail？

### 7.2 召回、多兴趣与多路融合：支撑「Borda Count 动态融合」

- [ ] [MIND: Multi-Interest Network with Dynamic Routing](https://arxiv.org/abs/1904.08030) — 阿里 CIKM 2019。一个用户多个兴趣向量。
  - 核心内容：一个用户不是一个兴趣向量，而是多个兴趣 capsule，用 dynamic routing 从行为序列中抽取多个兴趣。
  - 和召回连接：多兴趣向量可以分别召回不同类型 item，提升覆盖和多样性。
  - 和简历连接：Borda 融合多路召回，本质上也承认用户兴趣和召回信号是多源的。
  - 面试口径：多兴趣模型解决用户兴趣多样性，Borda 解决多召回源结果如何融合，二者在不同层次提升候选多样性。
  - 风险边界：多兴趣召回容易带来重复、同质化或低质量长尾，需要融合和重排控制。
- [ ] [ComiRec: Controllable Multi-Interest Framework](https://arxiv.org/abs/2005.09347) — KDD 2020。可控多兴趣召回。
  - 核心内容：在多兴趣召回基础上加入可控机制，在 accuracy 和 diversity 之间调节。
  - 和简历连接：你的固定 TopK 问题本质也是“召回源贡献不可控”，ComiRec 可作为可控召回的模型侧参考。
  - 面试口径：召回不是越准越好，还要控制多样性、覆盖和业务目标。
  - 风险边界：可控参数需要业务目标和线上实验校准，否则只是离线多样性好看。
- [ ] [TDM: Learning Tree-based Deep Model for Recommender Systems](https://arxiv.org/abs/1801.02294) — 阿里。树检索召回。
  - 核心内容：把 item 组织成树，通过逐层检索从大规模 item 库中高效找候选。
  - 和双塔/ANN 对比：双塔用向量近邻，TDM 用树结构分层搜索。
  - 和简历连接：说明召回方式很多，多路召回融合要能容纳不同 retrieval mechanism。
  - 面试口径：召回层目标是从百万/亿级 item 高效缩到千级，不同方法在覆盖、延迟、更新成本上不同。
  - 风险边界：树结构质量和更新成本会影响召回效果。
- [ ] [PinSage](https://arxiv.org/abs/1806.01973) — Pinterest KDD 2018。图卷积用于大规模推荐召回。
  - 核心内容：在 item/user graph 上用 random walk 采样邻居并训练图卷积 embedding。
  - 和简历连接：电商 I2I、U2I、共购、共点都可以构成图召回，和 MSM 的 Query-Ad 图也能类比。
  - 面试口径：图召回能利用行为关系补足文本/属性特征，尤其适合发现关联商品。
  - 风险边界：图会放大热门偏置，需要 degree correction 和探索。
- [ ] [Pixie: Random Walks on Pinterest Graph](https://dl.acm.org/doi/10.1145/3219819.3219846) — KDD 2018。图召回工业实践。
  - 核心内容：在 Pinterest 图上做个性化随机游走，实现实时相关内容推荐。
  - 和简历连接：可以解释图召回为什么适合工业系统：局部实时、可解释、和用户上下文相关。
  - 面试口径：图召回和 Borda 融合很搭，因为图召回通常是多路召回中的一路，有独特覆盖。
  - 风险边界：随机游走参数、图新鲜度和热门节点都会影响质量。
- [ ] [Reciprocal Rank Fusion](https://plg.uwaterloo.ca/~gvcormac/cormacksigir09-rrf.pdf) — RRF 排名融合。
  - 核心内容：用 `1 / (k + rank)` 汇总多个排序结果，头部结果权重更高，抗噪稳定。
  - 和 Borda 对比：Borda 线性使用 rank，尾部也有贡献；RRF 更重视各路头部。
  - 和简历连接：面试官问 Borda 替代方案时，可以主动比较 RRF、分数归一化、学习式融合。
  - 面试口径：Borda 适合低延迟、可解释、召回源多且常变化；RRF 适合更强调头部一致性的多检索器融合。
  - 风险边界：rank fusion 都会损失原始置信度。
- [ ] [Microsoft Recommenders](https://github.com/recommenders-team/recommenders) — 工业推荐算法样例库。
  - 核心内容：包含召回、排序、评估、数据处理的推荐系统示例和 benchmark。
  - 使用方式：用来复现 metrics、召回融合、排序模型，不必逐行读完。
  - 面试口径：我能把算法概念落到可运行 pipeline：数据、模型、评估、实验。
  - 风险边界：样例库和真实电商系统差距大，线上还要处理延迟、监控、分桶和回滚。
- [ ] [RecBole](https://github.com/RUCAIBox/RecBole) — 推荐系统实验框架。
  - 核心内容：统一实现多种推荐模型、数据集和评估指标，适合横向比较算法。
  - 使用方式：快速理解 Recall@K、NDCG、HitRate、MRR 等离线指标如何计算。
  - 面试口径：离线框架能帮助模型比较，但工业收益最终要靠线上 A/B。
  - 风险边界：公开数据集离线效果不能直接迁移到业务系统。

读完要能回答：

- 多路召回融合为什么不能直接加原始分？Rank 融合损失了哪些信息？
- Borda Count、RRF、归一化加权、Learning-to-rank 融合分别适合什么场景？
- 召回源经常上下线时，为什么简单、可解释、低延迟的方法反而更有工程价值？
- 如果某一路召回覆盖很广但转化差，权重该怎么下降？看 Hitrate 还是看最终转化？

### 7.3 样本偏差、延迟反馈、全链路解耦：支撑「全链路评估」

- [ ] [Counterfactual Learning and Evaluation for Recommender Systems](https://dl.acm.org/doi/10.1145/3240323.3240355) — 反事实评估。
  - 核心内容：线上日志只记录旧策略展示过的 item，新策略想展示的 item 可能没有 label，因此离线评估有偏。
  - 和简历连接：召回训练样本来自精排胜出日志，就是典型 policy bias / selection bias。
  - 面试口径：离线 Hitrate 高不代表线上涨，因为日志本身反映旧策略能看到什么。
  - 风险边界：反事实评估依赖 propensity 或随机探索数据，没有曝光概率就很难严格纠偏。
- [ ] [Doubly Robust Off-policy Evaluation](https://arxiv.org/abs/1103.4601) — DR 估计基础。
  - 核心内容：结合 direct method 和 inverse propensity weighting，在模型估计和 propensity 估计之间互相兜底。
  - 和简历连接：当 IPW 方差太高时，DR 是更稳的离线评估思路。
  - 面试口径：无偏评估不是只有 IPW，DR 用模型预测和曝光概率一起降低偏差/方差风险。
  - 风险边界：DR 也需要足够好的 reward model 或 propensity model，不能凭空评估未探索区域。
- [ ] [A/B Testing Intuition Busters](https://www.exp-platform.com/Documents/2017-08%20ABTestingIntuitionBusters.pdf) — Kohavi。线上实验常见坑。
  - 核心内容：很多实验直觉是错的，例如局部指标提升不一定整体收益提升，短期收益可能长期回落。
  - 和简历连接：UV value +12%、GMV +2.4% 需要说明分桶、guardrail、显著性和长期观察。
  - 面试口径：我不会只报一个 lift，会同时讲实验设计、切片一致性和保护指标。
  - 风险边界：实验结果受季节、活动、流量结构、novelty effect 影响。
- [ ] [Trustworthy Online Controlled Experiments](https://experimentguide.com/) — A/B 实验系统性材料。
  - 核心内容：实验生命周期、随机化、指标、样本量、统计显著性、guardrail、实验平台健康度。
  - 和简历连接：推荐系统收益必须靠线上随机实验验证，特别是小幅 GMV 或 UV value lift。
  - 面试口径：推荐系统上线不是离线 AUC/Hitrate 决定，而是 primary metric + guardrail + diagnostic 三层判断。
  - 风险边界：过早停止、sample ratio mismatch、指标选择错误都会让实验结论失真。
- [ ] [Feast Feature Store](https://docs.feast.dev/) — 特征平台参考。
  - 核心内容：管理离线/在线特征、point-in-time correctness、训练服务一致性。
  - 和简历连接：你的全场域优化涉及数据源配置化、样本构造、特征回填和线上生效，feature store 是工程背景。
  - 面试口径：推荐系统很多线上事故来自特征不一致，而不是模型结构本身。
  - 风险边界：特征平台解决管理问题，但数据质量、延迟和权限仍需监控。
- [ ] [Flink Stateful Stream Processing](https://nightlies.apache.org/flink/flink-docs-stable/docs/concepts/stateful-stream-processing/) — 延迟 Label、缓存区、回填都可以映射到状态流处理。
  - 核心内容：有状态流处理保存中间状态，支持 event time、watermark、window、state backend。
  - 和简历连接：延迟转化 label 需要缓存曝光样本，等转化窗口内事件回流再更新标签。
  - 面试口径：样本构造不是离线 SQL 一把梭，实时/近线场景要处理乱序、延迟和状态一致性。
  - 风险边界：状态过大、TTL 设置错误、事件时间处理错误会影响 label 准确性。

读完要能回答：

- 精排胜出日志为什么会让召回训练有偏？这个偏差属于 selection bias 还是 position bias？
- Exploration Traffic 比随机打散全量流量更安全在哪里？如何控制流量成本？
- 延迟 Label 归因窗口选 24h、72h、7d 的取舍是什么？
- 在线 A/B 收益和离线 Hitrate 冲突时，优先相信哪个？下一步怎么诊断？

## 11. 10 天冲刺路线

### Day 1：推荐系统全链路

- 画召回、粗排、精排、重排、混排、特征、样本、A/B、监控全链路。
- 明确你的三个项目分别落在哪：PID 排序、Borda 召回、Hitrate 解耦。

### Day 2：排序模型演进

- 复习 LR、GBDT+LR、Wide&Deep、DeepFM、DIN、DIEN、SIM。
- 输出：每个模型解决什么问题，为什么电商需要行为序列和兴趣演化。

### Day 3：多目标学习

- 复习 ESMM、MMoE、PLE、seesaw effect。
- 输出：pCTR、pCVR、GMV、UV value、体验指标之间如何冲突。

### Day 4：PID 控制

- 写 PID toy simulator：目标值、噪声、clipping、anti-windup。
- 输出：为什么成熟业务不用大规模 RL 乱探索。

### Day 5：召回体系

- 复习 CF、I2I、U2I、热门、图召回、双塔、ANN、多兴趣召回。
- 输出：十几路召回源的优缺点表。

### Day 6：Borda / RRF / 融合

- 手算 3 路召回融合。
- 输出：rank 融合、分数归一化、学习式融合的取舍。

### Day 7：样本偏差与延迟反馈

- 复习 ES-DFM、IPW、Doubly Robust、position bias、selection bias。

## 12. 公式与概念卡

### PID 动态调权

```text
error_t = target_t - observed_t
P_t = Kp * error_t
I_t = Ki * clamp(sum(error_i), lower, upper)
D_t = Kd * smooth(error_t - error_{t-1})
control_t = clip(P_t + I_t + D_t, -max_delta, max_delta)
```

面试解释：

- P 解决当前偏差，反应快。
- I 解决长期偏差，但容易 wind-up。
- D 预测趋势，但对噪声敏感，通常要平滑。
- 在线系统重点不是公式，而是 clipping、anti-windup、guardrail、rollback。

### 多目标排序分数

```text
score = w_ctr * pCTR
      + w_cvr * pCVR * price
      + w_value * long_term_value
      + w_rule * business_boost
```

风险：

- 各项量纲不同，必须校准或归一化。
- 短期 GMV 可能伤害长期留存。
- 业务 boost 需要上限，避免破坏模型排序。

### Borda Count

```text
rank_score_s(item) = K - rank_s(item) + 1
final_score(item) = sum_s source_weight_s * rank_score_s(item)
```

面试解释：

- Rank 融合解决分数尺度不同。
- Source weight 解决召回源质量不同。
- 去重、类目约束、多样性通常在融合后或重排阶段处理。

### Hitrate@K

```text
Hitrate@K = users_with_positive_item_in_topK / total_users
```

注意：

- Hitrate 是召回能力指标，不等于最终 GMV。
- 如果正样本来自精排曝光日志，Hitrate 本身会带精排偏见。
- 要结合 coverage、增量转化、下游通过率、探索样本看。

### 延迟反馈

```text
label_at_day0 = unknown, not negative
label_after_window = converted ? positive : negative
```

解释：

- 电商转化有时间延迟，当天未买不代表不喜欢。
- 过短窗口制造 fake negative，过长窗口降低训练新鲜度。

## 13. 阿里推荐系统设计模板

### 离线/近线/在线分层

| 层级 | 内容 | 关键点 |
| ---- | ---- | ------ |
| 离线 | 样本构造、特征回填、模型训练、召回索引 | 数据完整、训练稳定、可复现 |
| 近线 | 实时行为、增量特征、向量更新、规则配置 | 新鲜度、延迟、幂等 |
| 在线 | 召回、粗排、精排、重排、实验分桶 | 延迟、稳定、降级 |
| 监控 | 指标、分布、延迟、异常、A/B | 及时发现坏实验 |

### 推荐首页 5 分钟答案

1. 先定义目标：点击、加购、成交、GMV、UV value、长期体验。
2. 召回层多路生成：I2I、U2I、双塔、热门、类目、活动、新品探索。
3. 融合层用 Borda/RRF/配额策略控制召回源贡献和多样性。
4. 粗排用轻量模型筛到千级，精排用深模型打分。
5. 重排处理多样性、去重、疲劳、业务规则和探索。
6. 样本层处理延迟反馈、position bias、selection bias。
7. 实验层看 primary、guardrail、diagnostic，分场景切片。
8. 监控层看模型分布、特征缺失、召回量、延迟、回滚。

## 14. 项目复盘模板

### PID 排序复盘

- 背景：目标变化快，人工调权慢。
- 方案：把后链路 score/loss 权重做成闭环控制。
- 难点：指标噪声、延迟反馈、过冲、目标冲突。
- 保护：clipping、anti-windup、KL、AUC、A/B guardrail。
- 结果：UV value +12%。
- 边界：PID 适合小步稳定调控，不适合无约束探索。

### Borda 召回复盘

- 背景：多路召回固定 TopK，低效源占坑。
- 方案：按 rank 投票融合，source weight 由离线/在线评估闭环更新。
- 难点：召回源分数不可比、覆盖大但质量差、源间重叠。
- 保护：权重上限、去重后贡献、增量转化、探索接入。
- 结果：GMV +2.4%。
- 边界：Borda 简单稳，但不能表达复杂 item/source 交互。

### 全链路解耦复盘

- 背景：召回训练样本来自精排胜出日志，容易形成选择偏差。
- 方案：Hitrate 诊断 + exploration traffic + 召回来源泛化。
- 难点：探索流量有成本，离线指标和线上收益可能冲突。
- 保护：小流量、场景白名单、体验 guardrail、逐步 ramp。
- 结果：提升对召回真实增量的判断能力。
- 边界：探索数据也不是完全无偏，需要持续校正。

## 15. 高频追问答案素材

- Q：PID 的 error 是单指标还是多指标？
  - A：可以是单指标，也可以是归一化后的多指标组合。成熟系统里通常把主目标作为 error，把体验、延迟、投诉等做 hard guardrail。
- Q：为什么不直接重训模型？
  - A：重训周期长、风险大，不适合业务目标快速变化。后链路调权响应快，适合在模型稳定表达能力上做小步控制。
- Q：Borda 会不会损失原始置信度？
  - A：会，这是代价。换来的是跨源分布无关、低延迟、可解释。若召回源稳定且样本充足，可以进一步做学习式融合。
- Q：Hitrate 高但线上不涨怎么办？
  - A：看是否命中的是精排已经喜欢的旧分布、是否被粗排/精排过滤、是否缺少增量、是否正样本有偏、是否目标和 GMV/UV value 不一致。
- Q：探索流量怎么控制伤害？
  - A：低比例、白名单场景、只在候选池内探索、设置体验和转化 guardrail，异常自动回滚。
