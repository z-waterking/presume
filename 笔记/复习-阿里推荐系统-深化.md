## 3. PID 完整公式（带 anti-windup）

```text
e_t = target - measured_t
e_t_smooth = α·e_t + (1-α)·e_{t-1}_smooth         # 输入低通
P = Kp · e_t_smooth
I_raw = I_{t-1} + Ki · e_t_smooth · Δt
I = clamp(I_raw, I_min, I_max)                    # anti-windup
D = Kd · (e_t_smooth - e_{t-1}_smooth) / Δt
u_t = clip(P + I + D, -Δu_max, +Δu_max)           # rate limit
weight_{t+1} = clip(weight_t + u_t, w_min, w_max)
```

要点：
- **smoothing**：原始指标有噪声，必须先平滑。
- **anti-windup**：到边界后停积分，避免反向时反应迟钝。
- **rate limit**：每 tick 变化封顶，防一次震荡。
- **deadband**：误差小于 ε 不动，避免追噪声。

---

## 4. PID 调节点对比（追问标配）

| 调节点 | 响应 | 风险 | 适合 |
| ------ | ---- | ---- | ---- |
| Loss 权重 | 慢（小时-天） | 训练抖动 | 中长期 |
| **Score 融合权重** | **快（分钟）** | **排序分布漂移** | **日级业务调控 ✅** |
| Rerank quota | 快、可解释 | 表达力弱 | 活动 / 新品 / 类目保护 |

**默认讲法**：调 score 融合权重，响应快、可灰度、可回滚、不破坏模型本身。

---

## 5. PID vs Bandit vs RL

| 维度 | PID | Bandit | RL |
| ---- | --- | ------ | -- |
| 探索成本 | ~0 | 低 | 高 |
| 可解释 | 强 | 中 | 弱 |
| 上线门槛 | 低 | 中 | 高 |
| 适合 | 可观测连续指标 | arm 离散 | 长期回报 |

**一句话**：成熟电商对 GMV 和体验都有硬约束，不允许大规模无目的探索；PID 是最便宜也最稳的"小步闭环"。

---

## 6. PID 安全机制（每条都背）

1. clipping（每 tick） + rate limit（每 N tick）
2. anti-windup（积分饱和保护）
3. deadband（误差小不动）
4. KL/PSI 监控分数 / 曝光分布漂移
5. AUC/GAUC 跌破阈值自动 freeze
6. guardrail：CTR、投诉、延迟、CVR 越线触发降级
7. kill switch：一键回兜底权重

---

## 7. Borda Count 完整公式

```text
rank_score_s(item) = K - rank_s(item) + 1          # K 为该路 TopK
final(item) = Σ_s w_s · rank_score_s(item)
```

变种：
- **RRF**：`1 / (k + rank)`，强化头部。
- **Weighted MRR**：偏头部稳定性。
- **Logistic-weighted Borda**：尾部衰减更快。

---

## 8. Borda 白板例子

```text
I2I:        Item_A(1) → 100,  Item_B(3) → 98
U2I:        Item_A(5) → 96,   Item_C(1) → 100
Embedding:  Item_B(2) → 99,   Item_A(8) → 93

Item_A = w1·100 + w2·96 + w3·93   → 加权汇总最高 → 排第 1
```

为什么用 rank 不用分数：不同召回源分数分布不同（I2I [0,1]，Embedding [-100,100]），直接加无意义；rank 分布无关。

---

## 9. Borda 风险与对应处理

| 风险 | 处理 |
| ---- | ---- |
| 覆盖大的源天然拿更多票 | source weight 上限 + 去重后贡献评估 |
| Rank 丢弃原始置信度 | 高数据稳定场景上 learning-to-fuse 补充 |
| 高度重叠的源重复贡献 | 互补性矩阵 + 去重后净增量评估 |
| 新源冷启 | 小权重 + 灰度 + 多维 diagnostic + A/B 显著正向才进权重池 |

---

## 10. Borda vs MLP 融合（30 秒口径）

> Borda 胜在零训练、零延迟、强可解释、对召回源上下线鲁棒；MLP 表达力强但需大量稳定数据，召回源经常变化时维护成本高。我们把 Borda 当默认，少数高度稳定且数据丰富的场景上 learning-to-fuse。

---

## 11. Hitrate 高但线上不涨的 8 个原因（背全）

1. 命中的是精排原本就喜欢的旧分布，没增量。
2. 召回 item 被粗排或精排过滤，未到曝光。
3. Hitrate 正样本来自曝光日志，本身有 selection bias。
4. 召回扩大覆盖但相关性差，CTR/CVR 不升。
5. 召回源高度重叠，去重后净贡献小。
6. 离线评估窗口与线上流量分布不一致。
7. 长尾/新品 label 不足，被离线指标低估。
8. Hitrate@K 与 GMV/UV value 目标不一致。

---

## 12. 上下游耦合诊断（背）

1. 比较生产日志样本 vs 探索流量样本的 item / category 分布。
2. 看精排高分 item 在召回训练正样本中的占比是否异常高。
3. 看某些召回源 Hitrate 高但去重后曝光贡献低。
4. 看精排低估 item 在探索流量里是否有更高真实转化。

---

## 13. Exploration Traffic 详细方案

```text
1) 在指定场景（如首页 feed）划出 1-3% 流量作为 exploration bucket。
2) 候选池来自全量召回源，跳过精排打分（或用均匀采样）。
3) 控制 guardrail：CTR 下限、complaint 上限、退出率。
4) 收集无偏曝光-点击-转化数据。
5) 把这部分数据按一定权重混入召回训练样本，纠正 selection bias。
6) 同时反馈给精排：被精排长期低估、但探索数据显示高转化的 item，重新进入训练。
```

讲法：
> Exploration Traffic 不是为了探索新策略，是为了打破"精排筛选 → 召回学到 → 精排再筛"的封闭 loop。它是诊断工具，更是样本修正手段。

---

## 14. 延迟反馈完整方案

```text
- 归因窗口按品类设置（24h / 72h / 7d）
- 曝光样本进 buffer，未到窗口先标 "pending"
- 窗口到后回填 label
- 训练时使用：
   a) 已确认窗口内的样本：正常 label
   b) 窗口内的 pending：用 ES-DFM 给软 label 或概率加权
- 缓冲队列保持正负样本比例，避免 batch 偏移
```

---

## 15. Drop Rank 特征蒸馏

```text
1) 训练大模型 M_full，使用全量特征 F = {f1, ..., fN}
2) 对每个特征 f_i:
     M_drop_i = retrain 或 mask 后评估
     importance(f_i) = AUC(M_full) - AUC(M_drop_i)
3) 选 top 10% importance 特征作为蒸馏特征集 F*
4) 训练轻量 LTR 模型 M_light(F*)，部署到粗排
```

讲法：
> Drop Rank 是特征级蒸馏。比 weight-based importance 更准（看的是真实贡献），也比纯 SHAP 更适合大规模特征。粗排用蒸馏后的轻量模型，平衡效果和延迟。

## 16. 全场域优化（配套）

| 维度 | 做法 | 效果 |
| ---- | ---- | ---- |
| 样本侧 | 缓存区延迟 label + 缓冲队列保比例 | 避免 fake negative |
| 特征侧 | Drop Rank 蒸馏 top 10% 特征 | 粗排提速、效果稳 |
| 工程侧 | 数据源 → 样本 → 训练 → 上线 全配置化 | 多场域复用，新场域接入快 |
| 结果 | 各场域 IPV +2%, UV value +2%+ | 跨业务复用 |

## 17. 高频追问标准答案段（背 8 段）

1. **PID 比 RL 好在哪？** RL 需要探索，可能伤 GMV 和体验。PID 可解释、上线成本低、调参稳。业务只设目标和 guardrail，系统按误差动态调。

2. **多目标 error 怎么合成？** 不同指标先归一化到可比尺度，主目标进 error 加权；体验类作 hard guardrail，不进 error。

3. **Borda vs RRF？** Borda 用更多尾部信息；RRF 强调头部、抗噪。召回源多且要可解释 → Borda；搜索多检索器融合且头部最重要 → RRF。

4. **新召回源冷启？** 小权重 + 小流量 + 多维 diagnostic（coverage / 净贡献 / Hitrate / 通过率 / 转化）+ 至少一次 A/B 显著正向才进权重池。

5. **延迟反馈怎么处理？** 归因窗口按品类 + 缓存区回填 + ES-DFM 软 label；fake negative 是首要风险。

6. **Drop Rank？** 去掉某特征后排序变化 = 特征重要度。蒸馏 top 10% 给粗排或 LTR 轻量模型，平衡效果和延迟。

7. **Hitrate 高但线上不涨？** 8 大原因（见第 11 节），按"是否有增量、是否被过滤、是否有偏、是否相关、是否重叠、窗口、长尾、目标对齐"逐项查。

8. **怎么证明上下游耦合？** 4 步诊断（见第 12 节）：分布对比 + 正样本占比 + 去重贡献 + 探索数据转化对比。

## 18. 项目复盘三段式

### 18.1 PID 排序

- **背景**：业务目标变化快，人工调权周期天级。
- **方案**：在 fine-rank score 融合权重上闭环 PID；P+I 为主，D 平滑。
- **难点**：噪声、延迟反馈、过冲、目标冲突。
- **保护**：clipping、anti-windup、KL/PSI、AUC、guardrail、kill switch。
- **结果**：UV value +12%。
- **边界**：PID 适合连续指标小步调，不适合无约束探索。

### 18.2 Borda 召回

- **背景**：10+ 路召回固定 TopK，低效源占坑。
- **方案**：Borda Count 按 rank 投票，source weight 由离线/在线闭环更新。
- **难点**：覆盖大但质量差、源间高度重叠、新源冷启。
- **保护**：权重上限、去重后贡献、互补性矩阵、灰度 ramp。
- **结果**：GMV +2.4%。
- **边界**：Rank 丢失原始置信度；高度稳定数据可上 learning-to-fuse。

### 18.3 全链路解耦

- **背景**：召回正样本来自精排胜出日志，马太效应。
- **方案**：探索流量 + 修正 label + 召回源泛化。
- **难点**：探索流量有体验成本，离线/在线指标可能冲突。
- **保护**：低比例、白名单场景、guardrail、自动回滚。
- **结果**：诊断能力提升，长尾 item 转化 +X%。
- **边界**：探索流量也不完全无偏，需持续校正。

---

## 19. 边界声明

- 不说 PID 自动解决所有目标冲突；它需要目标、约束和 guardrail。
- 不说 Borda 一定优于模型融合；它胜在简单、低延迟、可解释、对召回源频繁变化鲁棒。
- 不说探索流量完全无偏；它只是比生产日志偏差更低，也需成本控制。
- 不只报 UV value / GMV；主动解释实验设计和保护指标。

---

## 20. 最后 20 秒收束

> 我在阿里的经验可以概括为：把推荐漏斗从局部调参推进到闭环优化。排序侧用 PID 做目标控制，召回侧用 Borda 做多源动态融合，全链路侧用 Hitrate 和探索流量诊断样本偏差。核心不是某个单点模型，而是让召回、排序、样本、实验形成可验证的闭环。
